# Feature Specification: 比賽加減分紀錄與趨勢圖（Match Score Timeline & Trend Chart）

**Feature Branch**: `[016-match-score-timeline]`

**Created**: 2026-09-09

**Status**: Draft

**Input**: User description: "對戰紀錄中，每一場比賽點進去，可以看到每一次加減分紀錄與對應時間，並繪製成圖表顯示趨勢圖"

## Clarifications

### Session 2026-09-09

- Q: 有些比賽會「跨越」本功能上線的時間點：比賽在上線前就已開打（當時還沒開始記錄逐次加減分），卻在上線後才結束。這種比賽只會有「部分」加減分紀錄（例如只有後半場的紀錄），該怎麼處理？ → A: 顯示現有的（不完整的）加減分紀錄與趨勢圖，並附上明確提示「此為部分紀錄，比賽前段未被記錄」，讓使用者知道資料不齊全但仍可參考。
- Q: 逐筆加減分紀錄與趨勢圖橫軸的「時間」，要用哪種格式呈現？ → A: 相對於開賽的經過時間（例如「開賽後 12 分 34 秒」），不同時段開打的比賽也能直接比較節奏與趨勢。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 點進比賽查看加減分紀錄 (Priority: P1)

我是會員或訪客，正在瀏覽「對戰紀錄」中的比賽清單（例如某團的對戰紀錄、我的跨團對戰紀錄，或某個團的歷史戰績），我想點進其中一場比賽，看到這場比賽從頭到尾每一次加分或扣分的紀錄——是哪一方、加了還是扣了一分、當下變成幾比幾、以及發生的時間。

**Why this priority**：這是本功能的核心價值——目前的對戰紀錄只顯示最終比分，看不出比賽過程如何拉鋸、是否有連續得分或修正扣分。沒有這份逐點紀錄，後續的趨勢圖也無從畫起。

**Independent Test**：任選一場「對戰紀錄」中已完成、且在本功能上線後才進行的比賽，點進去後可獨立驗證：畫面出現的每一筆加減分紀錄，其加減分方向、結果比分、開賽後經過時間，都與該場比賽實際發生的操作一致且依時間先後排列。

**Acceptance Scenarios**:

1. **Given** 一場已完成、且有加減分紀錄的比賽出現在對戰紀錄清單中, **When** 使用者點擊該場比賽, **Then** 系統 MUST 顯示這場比賽的每一筆加減分紀錄，依發生時間先後排序，每筆均標示：哪一方（A/B）、加或扣一分、該次操作後的比分、開賽後經過時間。
2. **Given** 使用者正在查看某場比賽的加減分紀錄, **When** 該比賽在過程中曾經扣分（例如操作失誤後修正）, **Then** 扣分紀錄 MUST 與加分紀錄並列呈現，不會被隱藏或合併。
3. **Given** 使用者對「對戰紀錄」清單原本就有查看權限（不論是會員或訪客身份）, **When** 使用者點進清單中的任一場比賽, **Then** 系統 MUST 直接顯示加減分紀錄，不要求額外的權限或登入。

---

### User Story 2 - 以趨勢圖檢視比分變化 (Priority: P2)

我是同一位使用者，除了看逐筆文字紀錄，我更想要一眼看出這場比賽雙方比分如何此消彼長——誰在什麼時間點領先、有沒有連續得分的段落、比賽是否緊咬到最後。

**Why this priority**：文字紀錄雖然完整，但要從一長串數字裡看出「趨勢」並不直覺；圖表能大幅降低理解成本，是這個功能相對於純文字紀錄清單的加值所在，因此次於「先要有資料可看」的 US1。

**Independent Test**：在已顯示加減分紀錄的比賽詳情畫面中，可獨立驗證：圖表上雙方比分隨時間變化的曲線，其終點數值與該場比賽的最終比分一致，且曲線的升降走勢與逐筆紀錄一致。

**Acceptance Scenarios**:

1. **Given** 一場比賽已有完整的加減分紀錄, **When** 使用者查看該比賽詳情, **Then** 系統 MUST 顯示一張圖表，以「開賽後經過時間」為橫軸，呈現雙方比分隨時間變化的趨勢。
2. **Given** 圖表已顯示, **When** 使用者比對圖表終點與比賽最終比分, **Then** 兩者 MUST 一致。
3. **Given** 比賽過程中出現扣分（修正）操作, **When** 使用者查看趨勢圖, **Then** 圖表上對應那一方的曲線 MUST 呈現下降，如實反映扣分，而非只呈現單調上升。

---

### User Story 3 - 沒有加減分紀錄時的清楚提示 (Priority: P3)

我是使用者，點進一場在本功能上線「之前」就已經完成的舊比賽（當時系統還沒有記錄逐次加減分），我希望看到清楚的提示告訴我「沒有這場比賽的加減分紀錄可看」，而不是空白畫面或看起來像故障的空圖表。

**Why this priority**：這是資料轉移期必然出現的情境（舊比賽沒有逐點紀錄，只有最終比分），優先度最低，但若不處理會讓使用者誤以為功能壞掉，影響對新功能的信任感。

**Independent Test**：找一場在本功能上線前已完成的比賽（或以其他方式讓資料庫沒有任何對應加減分紀錄的已完成比賽）點進去，可獨立驗證畫面明確顯示「無加減分紀錄」之類的提示，且不出現錯誤畫面或無意義的空白圖表。

**Acceptance Scenarios**:

1. **Given** 一場已完成的比賽在系統中沒有任何加減分紀錄, **When** 使用者點進這場比賽, **Then** 系統 MUST 顯示清楚的「無加減分紀錄」提示，MUST NOT 顯示錯誤訊息或空白圖表。

---

### Edge Cases

- 比賽因「提前結束」而中止（abandoned）：此類比賽依既有規則本就不會出現在「對戰紀錄」清單中，因此不在本功能範圍內考慮。
- 比賽於本功能上線前開打、上線後才結束：此類比賽只有部分加減分紀錄（見 FR-006a），MUST 顯示現有紀錄並註明不完整，MUST NOT 視為完全沒有紀錄而隱藏，也 MUST NOT 冒充為完整紀錄呈現。
- 兩筆加減分操作時間極為接近（例如手速很快連續點擊）：文字紀錄與趨勢圖 MUST 仍能依實際發生的先後順序清楚呈現，不可因時間顯示精度不足而合併成一筆或順序錯亂。
- 一場拉鋸很久、加減分次數非常多的比賽：文字紀錄與趨勢圖 MUST 仍完整呈現所有紀錄，不會因筆數多而截斷或遺漏。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 使用者從任一「對戰紀錄」清單（無論是單一團的對戰紀錄、會員本人跨團的對戰紀錄，或某團歷史戰績中的對戰紀錄）點擊一場已完成的比賽時，系統 MUST 提供該場比賽的詳情畫面。
- **FR-002**: 比賽詳情畫面 MUST 列出該場比賽的每一筆加減分紀錄，並依發生時間先後排序，每筆紀錄 MUST 包含：得／失分方（A 或 B）、本次為加分或扣分、該次操作後的比分、以「開賽後經過時間」（例如「開賽後 12 分 34 秒」）表示的發生時間點。
- **FR-003**: 比賽詳情畫面 MUST 提供一張趨勢圖，橫軸為「開賽後經過時間」，呈現雙方比分隨經過時間演進的變化曲線。
- **FR-004**: 趨勢圖呈現的最終比分 MUST 與比賽的正式最終比分一致；當比賽有扣分（修正）操作時，對應曲線 MUST 呈現下降。
- **FR-005**: 進入比賽詳情畫面所需的權限，MUST 與使用者目前查看該場比賽所在之「對戰紀錄」清單所需的權限相同——系統 MUST NOT 額外要求登入或更高權限，也 MUST NOT 因為新增此畫面而讓原本看不到某場比賽的人看得到。
- **FR-006**: 當某場已完成的比賽沒有任何加減分紀錄可用時（例如該比賽於本功能上線前已完成），比賽詳情畫面 MUST 顯示明確的「無加減分紀錄」提示，MUST NOT 顯示錯誤訊息、空白畫面或無意義的空圖表。
- **FR-006a**: 當某場已完成的比賽只有「部分」加減分紀錄可用時（例如比賽於本功能上線前開打、上線後才結束，只有上線後那段的紀錄），比賽詳情畫面 MUST 顯示現有的加減分紀錄與趨勢圖，並 MUST 附上明確提示告知使用者這是不完整的部分紀錄、比賽前段未被記錄，避免使用者誤以為圖表/紀錄涵蓋了整場比賽。
- **FR-007**: 比賽詳情畫面 MUST 同時顯示該場比賽的基本資訊（例如參賽者、所屬輪次、最終比分），使畫面本身資訊完整，不需使用者再返回清單比對。
- **FR-008**: 趨勢圖上區分 A、B 兩方曲線的方式 MUST NOT 僅依賴顏色，MUST 搭配至少一種非色彩的區分方式（例如線條樣式、圖示或文字標籤），確保色盲或無法辨色的使用者也能分辨兩條曲線分別代表哪一方（沿用專案既有無障礙原則）。

### Key Entities *(include if feature involves data)*

- **加減分紀錄（Scoring Action）**：一場比賽中單次加分或扣分的操作紀錄，包含所屬比賽、得／失分方、加或扣一分、該次操作後雙方比分、發生時間。已完成比賽的所有加減分紀錄依時間排序後，即構成該場比賽的完整比分演進過程。
- **比賽詳情（Match Detail）**：使用者點進「對戰紀錄」中某場比賽後看到的畫面，彙整該場比賽的基本資訊、加減分紀錄清單（依「開賽後經過時間」排序），以及依此繪製的比分趨勢圖；同時標示這份紀錄是「完整」「部分」還是「無」三態之一（見 FR-006、FR-006a），以便使用者判讀資料的完整程度。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者從任一「對戰紀錄」清單，只需一次點擊即可進入該場比賽的加減分紀錄與趨勢圖畫面。
- **SC-002**: 對於本功能上線後完成、且有加減分紀錄的比賽，畫面呈現的紀錄筆數與時間先後順序，與實際發生的加減分操作 100% 一致，無遺漏、無錯序。
- **SC-003**: 趨勢圖上顯示的雙方最終比分，與比賽正式最終比分 100% 一致。
- **SC-004**: 對於沒有加減分紀錄可用的已完成比賽，100% 顯示清楚的「無加減分紀錄」提示，而非錯誤畫面或空圖表。
- **SC-005**: 使用者僅憑趨勢圖（不需閱讀逐筆文字紀錄），即能判斷出比賽最終由哪一方獲勝、以及過程中是否出現扣分修正。

## Assumptions

- 本功能建立在既有「加減分紀錄」資料之上（每次加減分已被個別記錄，包含方向、結果比分與時間），本功能僅負責讓使用者「查得到、看得懂」這份資料，不改變記錄本身的產生方式。
- 「對戰紀錄」的定義沿用既有規格（specs/003、specs/007、specs/014）：僅列出已完成（非提前結束／未被捨棄）的比賽；本功能之詳情畫面亦僅適用於這些已完成的比賽。
- 趨勢圖橫軸與逐筆紀錄的時間，皆採用「相對於開賽的經過時間」（而非絕對時鐘時間，也非「第幾次得分」的序號），以呈現使用者描述中「與對應時間」的要求，讓比賽節奏（例如中場停頓、連續搶分）也能從圖上看出，且不同時段開打的比賽彼此可直接比較。
- 詳情畫面套用於所有現有的「對戰紀錄」清單入口（單一團對戰紀錄、會員跨團對戰紀錄、團歷史戰績中的對戰紀錄），維持一致的使用體驗，不特別區分入口而有不同權限或內容。
- 加減分紀錄中「由哪個操作介面送出」（例如控制面板、管理員後台等）屬於系統內部資訊，不需要在使用者看到的詳情畫面中呈現。
- 比賽進行中（尚未結束）的即時計分已有既有的即時比分功能可用；本功能之比賽詳情畫面僅提供「回顧已完成比賽」之用，不需要在比賽進行中即時更新。
- 在本功能上線之前「已完成」的比賽，因為系統當時尚未記錄逐次加減分，將完全沒有資料可顯示，屬於預期中的情況（見 User Story 3 / FR-006），不視為資料錯誤。若比賽是在上線前開打、上線後才結束，則屬於部分紀錄的情況，依 FR-006a 處理，與完全沒有紀錄的情況分開呈現。
