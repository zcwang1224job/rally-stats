# Feature Specification: 我的團最終團隊排名

**Feature Branch**: `[019-group-final-standings]`

**Created**: 2026-09-10

**Status**: Draft

**Input**: User description: "我的團 - 團戰績，解散後要有最終統計，像是組團團員申請後進入的頁面那種統計"

## Clarifications

### Session 2026-09-10

- Q: 最終團隊排名要涵蓋哪些人？現役成員以外，已離開或被踢除的成員要不要也出現在名單裡？ → A: 所有曾參與者（含已離開／被踢除）皆出現在名單中，並各自標示目前狀態；這與既有即時戰績頁（018-group-leaderboard）只保留現役成員的做法不同，也與本功能的存取權限範圍（曾經是正式成員即可查看）保持一致。
- Q: 團裡以「訪客」身份（沒有會員帳號）加入的參與者，要不要也出現在最終團隊排名的名單裡？ → A: 含訪客——只要曾經是該團的現役／已離開／已被踢除參與者，不論是否有會員帳號，皆出現在最終團隊排名中，與既有即時戰績頁（018-group-leaderboard）、既有對戰紀錄／對手排行（014-member-groups-history）的既有涵蓋範圍一致。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在「我的團」查看已解散團的最終團隊排名 (Priority: P1)

我是會員，我曾經加入或建立過一個團，這個團現在已經解散了。我希望在「我的團」點進這個團時，能看到全團所有人的最終排名與勝敗場次——就像現役成員在組團加入後看到的那個戰績排行榜一樣——而不是只看到我自己的個人戰績跟一份場次清單，這樣我才能知道整個團最後打完的結果是怎樣。

**Why this priority**：這是本功能存在的核心價值。團解散後，原本現役成員才看得到的即時戰績排行榜（`group-member-view` 的 standings 分頁）就此定型；「我的團」目前點進去只看得到「我自己」的統計與一份原始比賽清單，完全看不到「全團排名」這個既有畫面早就有的資訊，使用者得自己一場一場數才能知道誰打贏誰。

**Independent Test**：找一個已解散、且解散前已經打過數場比賽的團，會員從「我的團」點進這個團，驗證頁面上能看到全團所有曾參與者的最終名次、勝場數、敗場數，且排序與該團全部已完成比賽的實際勝負一致。

**Acceptance Scenarios**:

1. **Given** 一個團已解散，解散前已有數場比賽被標記為「已完成」，**When** 會員從「我的團」點進這個團的歷史頁面，**Then** 頁面 MUST 顯示一個「最終團隊排名」區塊，列出該團所有應涵蓋的參與者，並依已完成比賽的勝場數由高到低排序，每人可看到自己與其他人的名次。
2. **Given** 上述最終團隊排名區塊，**When** 會員查看自己所在的那一列，**Then** 該列 MUST 有清楚的文字/圖示標示（不僅靠顏色），讓會員一眼認出「這是我自己」。
3. **Given** 會員已經從這個團退出、被踢除，或這個團已經解散，**When** 會員從「我的團」點進去查看最終團隊排名，**Then** 系統 MUST 仍能成功顯示（唯讀），不得出現「無權限」之類的錯誤——存取權限的判斷基準與既有「我的團」歷史頁面（查看比賽清單與個人統計）完全一致，MUST NOT 採用即時戰績頁「僅限目前現役成員」的較嚴格規則。

---

### User Story 2 - 尚在進行中的團也能在「我的團」預覽同一份排名 (Priority: P2)

我是會員，我加入或建立的團還在進行中、尚未解散。我希望在「我的團」點進這個團時，也能看到同一份「最終團隊排名」區塊（呈現到目前為止的排名），這樣不管團有沒有解散，「我的團」都是我回顧任何一個團戰績的同一個地方，不需要另外去找現役成員才能看的即時戰績頁。

**Why this priority**：讓「我的團」對所有團（不論現役或已解散）都呈現一致的資訊結構，避免使用者困惑「為什麼這個團看得到排名，那個團看不到」；優先度低於 US1，因為即使只有已解散的團才顯示，US1 的核心價值（解散後看得到最終結果）依然成立。

**Independent Test**：找一個尚未解散、已經打過部分比賽的團，會員從「我的團」點進去，驗證同樣能看到「最終團隊排名」區塊，內容反映目前已完成比賽的累計戰績（非即時逐秒更新，載入當下的快照即可）。

**Acceptance Scenarios**:

1. **Given** 一個團尚未解散、已有部分比賽完成，**When** 會員從「我的團」點進這個團，**Then** 頁面 MUST 顯示「最終團隊排名」區塊，內容反映點擊當下該團已完成比賽的累計排名。
2. **Given** 上述情境，**When** 會員之後重新整理或再次點入同一個團，**Then** 排名 MUST 反映屆時最新的已完成比賽戰績（快照重新載入即可，不要求開著頁面時自動即時推播更新）。

---

### User Story 3 - 尚無比賽紀錄時的清楚提示 (Priority: P3)

我是會員，我點進的這個團完全沒有任何已完成的比賽，或裡面有成員完全還沒打過比賽。我希望畫面清楚告訴我「尚無比賽紀錄」，而不是顯示錯誤、空白，或讓我誤以為某人吊車尾。

**Why this priority**：這是既有戰績頁（018-group-leaderboard）已經處理過的既定體驗，延伸到「我的團」的最終排名區塊只是保持一致，不是本功能的核心價值，但沒處理好會讓使用者誤判資料異常。

**Independent Test**：找一個完全沒有已完成比賽的團，驗證最終團隊排名區塊整體顯示「尚無比賽紀錄」提示；找一個部分成員還沒打過比賽的團，驗證這些成員仍出現在清單中並個別標示「尚無比賽紀錄」，而非被排除或誤判為並列最後一名。

**Acceptance Scenarios**:

1. **Given** 一個團完全沒有任何已完成比賽，**When** 會員點進最終團隊排名區塊，**Then** MUST 顯示清楚的「尚無比賽紀錄」整體提示，不得顯示錯誤或空白畫面。
2. **Given** 某位應涵蓋的參與者完全沒有已完成比賽紀錄、但團內其他人已經打過比賽，**When** 會員查看最終團隊排名，**Then** 該位參與者 MUST 仍出現在清單中，並以明確文字標示「尚無比賽紀錄」，不得被排除在清單外，也不得被誤判為並列最後一名。

---

### Edge Cases

- 團的排點機制是「固定搭檔」時，最終團隊排名仍 MUST 以「個人」為排名單位，不是以「搭檔組合」為單位——同一場比賽的兩位搭檔各自獨立累計自己的勝敗場次（與既有 018-group-leaderboard 規則一致）。
- 兩位以上參與者的勝場數完全相同時，MUST 依「加入團的時間」排定顯示順序（先加入排前面），且並列名次之後的名次需跳號（例如兩人並列第 2 名，下一位是第 4 名）——與既有 018-group-leaderboard 規則一致，確保多次查看時順序穩定不變。
- 一場比賽被標記為「已捨棄」（abandoned，例如團解散時強制結束尚未打完的比賽）而不是「已完成」，這種比賽 MUST NOT 計入任何人的最終戰績。
- 同一位會員在同一個團有多筆歷史紀錄（例如先退出後又重新加入）——最終排名清單中只需列出這個人一次，統計涵蓋其在該團全部參與期間的所有已完成比賽，比照既有「我的團」清單本身的既有慣例。
- 一個團尚無任何已完成比賽也尚無任何參與者以外的資料狀態異常——不得顯示誤導性的空白或錯誤畫面（見 User Story 3）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 在「我的團」點進任一團後的歷史頁面中，新增一個「最終團隊排名」區塊，與既有的「我的戰績」（個人統計）、「對戰紀錄」（全團比賽清單）兩區塊並存，不取代既有內容。
- **FR-002**: 最終團隊排名 MUST 涵蓋該團所有曾參與過的人——不論目前狀態為現役、已離開，或已被踢除，也不論是否擁有會員帳號（含以訪客身份加入者），皆 MUST 出現在清單中；MUST NOT 比照既有即時戰績頁（018-group-leaderboard FR-008）只保留現役成員、排除離團成員的做法，因為本功能是「最終／完整」的回顧統計，涵蓋範圍 MUST 與 FR-010 的存取權限範圍（曾經是正式成員即可查看）保持一致。訪客參與者 MUST NOT 因為沒有會員帳號而被排除或另外特別標示為與一般參與者不同的類別。
- **FR-003**: 排名 MUST 依「已完成比賽的勝場數」由高到低排序（贏最多場排最前），MUST 只計入狀態為「已完成」的比賽，MUST NOT 計入仍在排隊中、進行中，或已被捨棄（abandoned）的比賽。
- **FR-004**: 排名 MUST 累計該團「自成立以來」的所有已完成比賽，不分輪次或賽季重置，與既有戰績計算基準（018-group-leaderboard、014-member-groups-history）一致。
- **FR-005**: 兩位以上參與者依 FR-003 核心排名指標（勝場數）完全相同時，系統 MUST 依「加入團的時間」排定顯示順序（先加入的排在前面），並列名次之後的名次 MUST 跳過對應的名次數量，確保同一份資料重新查看時順序保持穩定不變。
- **FR-006**: 最終團隊排名 MUST 為每一位涵蓋的參與者顯示：目前名次、暱稱、已完成比賽場次、勝場數、敗場數；對於已離開或已被踢除的參與者，MUST 額外標示其目前狀態（例如「已離開」／「已被踢除」），與現役成員區隔開來。
- **FR-007**: 尚未有任何已完成比賽紀錄的參與者 MUST 仍出現在最終團隊排名清單中，並以明確文字（例如「尚無比賽紀錄」）與已經打過比賽但戰績掛零的參與者區隔開來，MUST NOT 被清單排除在外，也 MUST NOT 被誤判為並列最後一名。
- **FR-008**: 若該團完全沒有任何已完成比賽，最終團隊排名區塊 MUST 顯示清楚的「尚無比賽紀錄」整體提示，不得顯示錯誤或空白畫面。
- **FR-009**: 排點機制為「固定搭檔」的團，最終團隊排名 MUST 以個人為單位計算勝敗場次——同一場比賽的兩位搭檔 MUST 各自獨立累計自己的勝敗紀錄，MUST NOT 以搭檔組合作為排名單位。
- **FR-010**: 查看最終團隊排名的存取權限，判斷基準 MUST 與既有「我的團」歷史頁面（查看比賽清單、個人統計）完全一致——只要曾經是該團的正式成員（不論現役／已離開／被踢除）即可查看，不論該團目前是否已解散；MUST NOT 採用即時戰績頁「僅限目前現役成員」的較嚴格規則，也 MUST NOT 允許從未加入過該團的會員查看。
- **FR-011**: 使用者自己所在的排名列 MUST 同時使用文字/圖示與視覺樣式標示，MUST NOT 僅依賴顏色作為唯一的辨識依據。
- **FR-012**: 最終團隊排名區塊 MUST 對「已解散」與「尚未解散」的團都顯示（呈現點擊當下該團已完成比賽的累計快照），MUST NOT 僅限已解散的團才顯示；不要求開著頁面時自動即時推播更新，重新載入頁面反映最新資料即可。

### Key Entities *(include if feature involds data)*

- **最終團隊排名列（衍生視圖，非新資料表）**：代表一位參與者在「我的團」歷史頁面上的最終排名狀態，包含名次、已完成場次、勝場數、敗場數。完全由既有的比賽與戰績紀錄計算而得，本身不是一筆需要獨立維護生命週期的資料。
- **（既有）Group（團）**：本功能唯讀，查詢範圍涵蓋現役與已解散的團。
- **（既有）RosterEntry（輪替名單項目）**：本功能唯讀，決定「誰曾經加入過這個團」，是計算最終排名涵蓋範圍的依據（涵蓋範圍細節見 FR-002）；包含以會員身份加入與以訪客身份加入兩種，兩者在最終排名中一視同仁。
- **（既有）Match（比賽）**：本功能唯讀，用於計算最終團隊排名的勝負與場次。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：會員從「我的團」點進任一個曾經參加過的團（不論現役、已離開、被踢除，或該團已解散），能在 3 秒內於同一個頁面上看到該團的最終團隊排名，不需要跳轉到其他頁面或自行計算。
- **SC-002**：已解散的團，最終團隊排名 100% 準確反映該團解散當下累計的已完成比賽戰績，不會因解散而遺漏或誤算場次。
- **SC-003**：已離開、被踢除的會員，或該團已解散，查看最終團隊排名的成功率達 100%，不會遇到「無權限」錯誤。
- **SC-004**：尚未打過比賽的參與者，100% 被正確標示為「尚無比賽紀錄」，不會被誤判為敗場掛零或佔用最後一名的排序位置。
- **SC-005**：對於同一份戰績資料，不論重新整理幾次，100% 的情況下最終團隊排名計算出的名次與順序完全一致（可重現、不隨機跳動）。

## Assumptions

- 「已完成比賽」的定義沿用既有系統慣例（比賽狀態為已完成），排除排隊中／進行中／已捨棄的比賽——與既有 018-group-leaderboard、014-member-groups-history 一致。
- 本功能是既有「我的團」歷史頁面（014-member-groups-history 定義的 group-history 頁面）的擴充，新增一個獨立區塊，MUST NOT 取代既有的「我的戰績」（個人統計）與「對戰紀錄」（全團比賽清單）兩區塊，也 MUST NOT 另外新增一個平行存在的獨立畫面/路由。
- 最終團隊排名區塊採「點擊當下快照」呈現，不要求比照 018-group-leaderboard 即時戰績頁的秒級自動推播更新——這是既有「我的團」歷史頁面本來就沒有即時同步機制的既定範圍，重新整理頁面即可看到最新資料。
- 名次計算規則（並列判斷、跳號、次要排序依據為加入時間、固定搭檔以個人為單位）直接沿用既有 018-group-leaderboard 已定義的規則，不重新設計一套不同的排名邏輯。
- 清單規模比照既有「我的團」與既有戰績頁的既有 Scale/Scope 假設（單一團的參與者數量在可全部載入前端處理的規模），暫不特別設計分頁機制。
