# Feature Specification: 快速開始比賽（不開團）

**Feature Branch**: `[042-quick-match]`

**Created**: 2026-09-22

**Status**: Draft

**Input**: User description: "我想要做一個「快速開始比賽，不開團」的功能——建立 042-quick-match 規格"

## 背景

目前系統裡每一場比賽都必須先「開團」才能存在：填團名、設定人數上限與排程機制、
拿到組團編號與管理 PIN、進管理頁、產生場地連結，最後才能開始計分。這個流程對
「揪一群人打一整個下午」很合理，但對最常見的另一種情境——兩個人（或四個人）
球場上臨時想打一場、只想要一個計分板與一份戰績——太重了。

本功能提供一條平行的捷徑：使用者在首頁按「快速開始比賽」，填最少的資訊
（單打或雙打、誰跟誰打、用哪種計分制），按下去就直接進到控制板開始計分。
整個過程中使用者不需要理解「團」「組團編號」「管理 PIN」「排程機制」這些概念。
比賽打完的戰績、逐點紀錄、分享卡與會員對戰紀錄，與一般團內比賽完全一樣。

## Clarifications

### Session 2026-09-22

- Q: 沒有登入的訪客可以用快速比賽嗎？ → A: 可以（採建議預設值，待使用者確認）。沿用系統
  「高頻現場操作免註冊」的原則；訪客的戰績只有在事後綁定帳號時才會歸戶（沿用 028）。
- Q: 快速比賽進行中可以再加人或用連結／QR 讓別人加入嗎？ → A: 第一版不開放（採建議預設值，
  待使用者確認）。人數在開始時就固定為 2 人或 4 人，之後只能整場「換人再打」；加入連結
  留給後續版本。
- Q: 快速比賽要不要出現在「我的團」？ → A: 預設不出現（採建議預設值，待使用者確認）。
  「我的團」是揪團活動的清單；快速比賽只出現在對戰紀錄、統計分析與分享卡，並掛
  「快速比賽」標籤。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 從首頁到開始計分只要一頁 (Priority: P1)

我是球場上臨時想打一場的球友，我不想開團、不想取團名、不想記組團編號和 PIN。
我希望在首頁按一顆「快速開始比賽」，在一個畫面上選單打或雙打、填上場的人、
選計分制，按下「開始」之後就直接看到控制板可以按 +1，並且能把計分板連結或
QR 給對手或旁邊的人看。

**Why this priority**: 這是本功能存在的理由——把「想打一場」到「可以按 +1」之間的距離
壓到最短。沒有這一項，其餘故事都沒有意義。

**Independent Test**: 以訪客身分開首頁 → 按「快速開始比賽」→ 選單打、填兩個暱稱、
維持預設計分制 → 按「開始」→ 驗證直接落在該場比賽的控制板，能按 +1，且畫面上有
計分板連結與 QR；全程不曾出現團名、組團編號、管理 PIN、排程機制等欄位或文字。

**Acceptance Scenarios**:

1. **Given** 使用者（登入會員或訪客）在首頁，**When** 按「快速開始比賽」，**Then** 系統 MUST
   顯示一個單頁表單，欄位只有：比賽模式（單打／雙打）、上場球員、計分制（21 分制／
   15 分制／自訂）、比賽詳細設定開關；MUST NOT 出現團名、人數上限、排程機制、通關密碼等
   開團專屬欄位。
2. **Given** 使用者選了單打，**When** 查看球員欄位，**Then** 系統 MUST 剛好要求 2 位球員
   （A 方 1 位、B 方 1 位）；選雙打則 MUST 剛好要求 4 位（每方 2 位）。
3. **Given** 登入會員開啟表單，**When** 表單載入完成，**Then** A 方第一位球員 MUST 已自動帶入
   會員本人的暱稱且標示為本人；訪客則 MUST 自行填入所有球員暱稱。
4. **Given** 表單填寫完整，**When** 按「開始」，**Then** 系統 MUST 建立一場「進行中」的比賽並
   直接把使用者導向該場比賽的控制板；控制板 MUST 與既有單一場地控制板功能一致
   （+1／-1、提前結束、決勝分二次確認、詳細計分模式）。
5. **Given** 使用者已在控制板，**When** 查看畫面，**Then** 系統 MUST 提供該場的計分板連結與
   QR，供對手或旁觀者不登入即可開啟觀看。
6. **Given** 表單有欄位不合法（暱稱空白、同方兩人同名、球員數不足），**When** 按「開始」，
   **Then** 系統 MUST 就地提示錯誤並 MUST NOT 建立任何比賽資料。

### User Story 2 - 計分、結束與戰績跟一般比賽一模一樣 (Priority: P1)

我是正在打快速比賽的球友，我希望計分的規則、決勝分的確認、打完自動結束、逐點紀錄、
發球與落點紀錄、分享卡，都跟我在團裡打的比賽完全相同；打完之後這一場也要跟其他比賽
一樣出現在我的對戰紀錄裡，而不是另一套「不算數」的比賽。

**Why this priority**: 若快速比賽的戰績是另一套規則或不計入紀錄，使用者就沒有理由用它，
會退回去開團。與既有比賽「一模一樣」也是控制範圍的關鍵——本功能不重新發明計分。

**Independent Test**: 開一場 21 分制快速比賽，用控制板把 A 方打到 21:19 → 驗證系統自動
判定 A 方勝、比賽結束並計入戰績；以登入會員身分開「對戰紀錄」→ 驗證該場出現、逐點
趨勢圖可看、分享卡可產生，且列表上標示「快速比賽」。另開一場並「提前結束」→ 驗證該場
為「已捨棄」，不計入任何人的勝敗。

**Acceptance Scenarios**:

1. **Given** 快速比賽進行中，**When** 一方達到計分制的獲勝條件，**Then** 系統 MUST 依既有規則
   自動結束比賽、判定勝方並計入戰績，處理方式 MUST 與團內比賽完全相同。
2. **Given** 快速比賽開始時採用的計分制與詳細設定，**When** 比賽進行中，**Then** 這些設定
   MUST 在整場比賽維持不變（沿用既有的「開賽當下設定快照」原則）。
3. **Given** 快速比賽進行中，**When** 計分員按「提前結束」，**Then** 該場 MUST 轉為「已捨棄」、
   MUST NOT 計入任何一方勝負（沿用憲章的統一原則）。
4. **Given** 登入會員參與了一場已完成的快速比賽，**When** 開啟「對戰紀錄」或「統計分析」，
   **Then** 該場 MUST 出現，統計 MUST 把它與團內比賽一併計算，列表上 MUST 以「快速比賽」
   標籤取代團名。
5. **Given** 快速比賽已完成，**When** 使用者在比賽紀錄上點「分享」，**Then** 系統 MUST 能產生
   與一般比賽相同的分享卡，卡片上的活動名稱 MUST 顯示為「快速比賽」。
6. **Given** 對手或旁觀者開著計分板連結，**When** 計分員在控制板按 +1，**Then** 計分板 MUST
   即時更新，與既有計分板的同步行為一致。

### User Story 3 - 再打一場／換人再打 (Priority: P2)

我是剛打完一場快速比賽的球友，我們常常會馬上再打一場（換邊），或是旁邊有人要換上來。
我希望在比賽結束的畫面上直接按「再打一場」或「換人再打」，不用回首頁重新填一次。

**Why this priority**: 現場一次通常不只打一場；沒有這項，第二場開始就退回到「重填表單」，
但第一場的核心價值（US1、US2）已經成立。

**Independent Test**: 打完一場快速比賽 → 按「再打一場」→ 驗證新的一場立刻開始、兩方球員
互換場邊、控制板連結與計分板連結不變；再打完 → 按「換人再打」→ 修改其中一位球員暱稱後
開始 → 驗證新的一場以新名單開始，且三場都各自出現在對戰紀錄裡。

**Acceptance Scenarios**:

1. **Given** 快速比賽結束（自然結束或提前結束），**When** 結束畫面顯示，**Then** 系統 MUST 提供
   「再打一場」「換人再打」「結束」三個動作。
2. **Given** 使用者按「再打一場」，**When** 新比賽開始，**Then** 名單 MUST 相同、兩方 MUST 互換
   場邊、計分制與詳細設定 MUST 沿用上一場；控制板與計分板連結 MUST 維持不變，正在看計分板
   的人 MUST 自動看到新的一場。
3. **Given** 使用者按「換人再打」，**When** 修改名單，**Then** 系統 MUST 允許替換任一位球員
   （登入會員本人除外，見 FR-013），並可切換單打／雙打，其餘規則同 US1。
4. **Given** 使用者按「結束」，**When** 確認後，**Then** 本次快速比賽 MUST 收尾：控制板與
   計分板連結 MUST 失效，已完成的比賽紀錄 MUST 保留。
5. **Given** 開始快速比賽的人關掉頁面又回來，**When** 該次快速比賽尚未收尾，**Then** 登入會員
   MUST 能從首頁看到「你有一場進行中的快速比賽」並回到控制板；訪客 MUST 能以原本的
   控制板連結回到同一場。

### User Story 4 - 戰績歸戶 (Priority: P2)

我是登入會員，我希望快速比賽自動算在我自己頭上；如果對手也是系統會員，我希望可以直接
從好友清單挑他，讓這場也算進他的戰績。對手不是會員的話，就當作訪客打，之後他想要的話
可以再綁定帳號。

**Why this priority**: 歸戶是「戰績一模一樣」的延伸——沒有它，會員本人仍會被歸戶
（US1 已自動帶入本人），但對手永遠只是一個暱稱。

**Independent Test**: 以會員 A 登入、從好友清單挑好友 B 當對手開單打 → 打完 → 以 B 登入
開「對戰紀錄」→ 驗證該場出現在 B 的紀錄且勝負方向正確；再開一場對手填純暱稱 →
打完後對手用計分板上的「建立帳號並綁定戰績」→ 驗證綁定成功（沿用 028）。

**Acceptance Scenarios**:

1. **Given** 登入會員填球員欄位，**When** 點選某個球員欄位，**Then** 系統 MUST 提供「從好友挑選」
   與「直接輸入暱稱」兩種方式。
2. **Given** 選了好友 B，**When** 比賽完成，**Then** 該場 MUST 同時出現在 A 與 B 的對戰紀錄，
   並且 MUST 在雙方的「好友對戰紀錄」中可見。
3. **Given** 選的好友目前正在別的團裡活動中，**When** 按「開始」，**Then** 系統 MUST 拒絕並
   指名該位好友，提示可改以暱稱方式（不歸戶）加入。
4. **Given** 對手以純暱稱（訪客）參賽且比賽已完成或進行中，**When** 對手在計分板上選擇
   「建立帳號並綁定戰績」，**Then** 綁定流程 MUST 與既有團內比賽相同。

---

### User Story 5 - 不干擾既有的揪團畫面 (Priority: P3)

我是用開團列表找場次的球友，也是常看「我的團」的會員。我不希望別人的快速比賽塞滿
開團列表，也不希望我的「我的團」被幾十筆一次性的快速比賽淹沒。

**Why this priority**: 這是保護既有功能的邊界條件；沒有它功能仍可用，但體驗會逐漸變差。

**Independent Test**: 建立幾場快速比賽 → 開「開團列表」驗證一筆都沒出現；以參與者身分開
「我的團」驗證預設不列出快速比賽；開「對戰紀錄」驗證它們仍在。放著一場快速比賽不動超過
收尾期限 → 驗證系統自動收尾、連結失效、已完成紀錄仍在。

**Acceptance Scenarios**:

1. **Given** 系統中存在進行中的快速比賽，**When** 任何人開啟開團列表或搜尋場次，**Then** 快速
   比賽 MUST NOT 出現。
2. **Given** 會員參與過快速比賽，**When** 開啟「我的團」，**Then** 清單預設 MUST NOT 列出快速
   比賽；對戰紀錄與統計分析 MUST 照常包含它們。
3. **Given** 一次快速比賽最後一次動作距今超過收尾期限（預設一天），**When** 系統執行例行檢查，
   **Then** 系統 MUST 自動收尾：進行中的比賽轉「已捨棄」、連結失效、已完成的比賽紀錄保留。
4. **Given** 快速比賽已收尾，**When** 有人開啟舊的控制板或計分板連結，**Then** 系統 MUST 顯示
   「這場快速比賽已結束」而非錯誤畫面。

---

### Edge Cases

- 登入會員目前已在某個團裡活動中（系統規則：一位會員同時只能在一個團活動）。按
  「快速開始比賽」時 MUST 拒絕並說明「你目前在『XX 團』中，請先退出或等該團結束」，
  不得同時存在。
- 反過來，會員有一次尚未收尾的快速比賽，又去開團或加入團：若該次快速比賽沒有進行中的
  比賽，系統 MUST 自動把它收尾後放行；若有比賽正在進行中，MUST 拒絕並提示先結束那一場。
- 同一方填了兩個相同的暱稱、或兩方出現同一位好友：MUST 就地提示，不得開始。
- 訪客暱稱與登入會員本人暱稱相同（例如都叫「小明」）：允許，但畫面上本人 MUST 有「本人」
  標示以資區別。
- 訪客開了快速比賽後關掉分頁且沒有保存控制板連結：無法回到該場；那一場會在收尾期限後
  自動收尾。表單送出後 MUST 明確提示「請保留這個頁面或連結，關掉就找不回來」。
- 自訂計分制的數值不合法（目標分數、deuce 門檻、封頂分數的關係違反既有規則）：沿用既有
  開團時的驗證與錯誤訊息。
- 雙打的發球輪替與站位顯示（029／030）：快速比賽 MUST 沿用既有邏輯，開始時的站位依球員
  填寫順序決定。
- 同一位使用者短時間內大量建立快速比賽：沿用開團流程既有的機器人防護與速率限制。
- 「再打一場」時上一場是「已捨棄」（提前結束）：仍允許再打，名單與設定沿用。
- 收尾期限剛好在比賽進行中到期：進行中的比賽 MUST 轉「已捨棄」（與解散團一致），不得
  留下永久「進行中」的比賽。

## Requirements *(mandatory)*

### Functional Requirements

**入口與表單**

- **FR-001**: 首頁 MUST 提供「快速開始比賽」入口，與既有「開團」入口並列，登入會員與訪客
  皆可使用。
- **FR-002**: 快速開始表單 MUST 只包含：比賽模式（單打／雙打，預設單打）、上場球員、計分制
  （21 分制／15 分制／自訂，預設 21 分制）、比賽詳細設定開關（預設關閉）。MUST NOT 出現
  團名、人數上限、排程機制、通關密碼、組團編號、管理 PIN。
- **FR-003**: 球員數 MUST 依比賽模式固定：單打每方 1 人、雙打每方 2 人；不得多也不得少。
- **FR-004**: 登入會員開啟表單時，A 方第一位 MUST 自動帶入本人且不可移除；訪客 MUST 自行
  填入全部球員暱稱。
- **FR-005**: 每一位非本人的球員欄位 MUST 支援兩種輸入方式：登入會員可「從好友挑選」
  （歸戶到該好友），任何人都可「直接輸入暱稱」（視為訪客）。
- **FR-006**: 表單 MUST 就地驗證：暱稱不可空白、同一場內暱稱不可重複、同一位好友不可重複、
  自訂計分制數值 MUST 符合既有開團的驗證規則。驗證失敗 MUST NOT 建立任何資料。
- **FR-007**: 快速開始 MUST 沿用開團流程既有的機器人防護（驗證失敗一律拒絕）與速率限制。

**開始與計分**

- **FR-008**: 按「開始」成功後，系統 MUST 在同一個成功／失敗單位內完成：建立本次快速比賽、
  建立一個場地、登記全部球員、建立一場「進行中」的比賽。任一步失敗 MUST 全部回復。
- **FR-009**: 開始成功後 MUST 直接導向該場比賽的控制板，並在控制板上提供計分板連結與 QR。
- **FR-010**: 快速比賽的計分、決勝分二次確認、詳細計分（發球者、站位、落點、結束方式）、
  提前結束、撤銷完賽、即時同步，MUST 全部沿用既有單一場地控制板與計分板的行為，
  不得另立規則。
- **FR-011**: 快速比賽開始時採用的計分制與詳細設定 MUST 以快照方式固定於該場比賽，比賽中
  不得變更。
- **FR-012**: 自然結束的快速比賽 MUST 計入所有歸戶球員的戰績與對戰紀錄；提前結束或因收尾
  而中止的比賽 MUST 轉為「已捨棄」且不計入任何勝負。

**再打一場**

- **FR-013**: 比賽結束畫面（控制板）MUST 提供「再打一場」「換人再打」「結束」。「再打一場」
  MUST 以相同名單、互換場邊、相同設定立刻開始新的一場；「換人再打」MUST 允許修改名單
  與比賽模式後開始，但登入會員本人 MUST 仍在名單中；「結束」MUST 經二次確認後收尾。
- **FR-014**: 同一次快速比賽內連續打的多場，MUST 共用同一組控制板與計分板連結；正在觀看
  計分板的人 MUST 自動切換到新的一場。
- **FR-015**: 同一次快速比賽內每一場都 MUST 是獨立的比賽紀錄，各自出現在對戰紀錄中。

**歸戶與呈現**

- **FR-016**: 快速比賽 MUST 出現在每位歸戶會員的「對戰紀錄」「統計分析」「好友對戰紀錄」
  「球員儀表板」與各種洞察／比較中，與團內比賽一併計算，不得被排除。
- **FR-017**: 在上述所有列表、詳情與分享卡上，快速比賽的活動名稱 MUST 顯示為「快速比賽」
  （依語系），並 MUST 可用篩選條件只看或排除快速比賽。
- **FR-018**: 訪客身分參賽的球員 MUST 能透過既有「建立帳號並綁定戰績」流程把快速比賽的戰績
  綁定到新帳號。
- **FR-019**: 快速比賽 MUST NOT 出現在開團列表與場次搜尋；「我的團」預設 MUST NOT 列出
  快速比賽（可由篩選條件顯示）。

**生命週期與併存規則**

- **FR-020**: 登入會員同時只能有一次進行中的快速比賽，且與「同時只能在一個團活動」的既有
  規則共用：會員在團內活動中 MUST 不能開始快速比賽；反之有未收尾的快速比賽時要開團或
  加入團，若無比賽進行中 MUST 自動收尾後放行，若有比賽進行中 MUST 拒絕。
- **FR-021**: 登入會員有未收尾的快速比賽時，首頁 MUST 顯示提示並提供回到控制板的入口。
- **FR-022**: 一次快速比賽自最後一次動作起閒置超過收尾期限 MUST 自動收尾；期限 MUST 是可由
  系統共用設定調整的參數，預設一天。
- **FR-023**: 收尾（手動或自動）MUST：把進行中的比賽轉「已捨棄」、讓控制板與計分板連結失效、
  保留所有已完成的比賽紀錄與歸戶結果。開啟失效連結 MUST 顯示「這場快速比賽已結束」。
- **FR-024**: 訪客開始的快速比賽，表單送出成功後 MUST 明確提示保留頁面或連結；系統不提供
  訪客的找回機制。
- **FR-025**: 快速比賽 MUST NOT 提供加入連結、QR 加入、邀請好友入團、場地管理、排程管理等
  團專屬功能（第一版）。
- **FR-026**: 所有新增文字 MUST 提供中文與英文語系。

### Key Entities

- **快速比賽（Quick Session）**: 一次「按快速開始」所產生的活動單位，可包含連續多場比賽。
  它與「團」是同一類的活動紀錄，但標記為快速類型：沒有可見的團名（顯示為「快速比賽」）、
  沒有加入方式、固定一個場地、固定人數、以手動指定名單的方式產生比賽。有建立者
  （會員或訪客）、最後動作時間、狀態（進行中／已收尾）。
- **快速比賽的球員**: 該次活動中登記的球員，每位可為本人、好友（歸戶會員）或訪客暱稱；
  與團內的名單成員是同一種紀錄。
- **比賽（Match）**: 沿用既有比賽紀錄，包含逐點紀錄、發球、落點、快照的計分制；快速比賽
  中的每一場都是一筆獨立的比賽紀錄。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者從首頁按下「快速開始比賽」到在控制板按下第一個 +1，只經過一個表單頁面，
  且在 60 秒內可完成（含填兩個暱稱）。
- **SC-002**: 快速開始表單上出現的欄位不超過 4 組（比賽模式、球員、計分制、詳細設定），
  且不出現任何「團」相關用語。
- **SC-003**: 快速比賽在對戰紀錄、統計分析、分享卡上的呈現與團內比賽相同，唯一差異是活動
  名稱顯示為「快速比賽」；歸戶會員的勝敗統計把快速比賽 100% 納入。
- **SC-004**: 開團列表中出現的快速比賽數量為 0；「我的團」預設列表中出現的快速比賽數量為 0。
- **SC-005**: 連續打三場時，第二、三場各只需一次點擊（「再打一場」）即可開始，計分板觀看者
  不需重新整理即看到新的一場。
- **SC-006**: 閒置超過收尾期限的快速比賽在期限後一小時內全部自動收尾，系統中不存在超過期限
  仍「進行中」的快速比賽。
- **SC-007**: 90% 的首次使用者不需說明即可完成「開始一場快速比賽並計到結束」。

## Assumptions

- **三項採建議預設值、尚待使用者確認的決定**（見 Clarifications）：訪客可用；第一版不開放
  中途加入；快速比賽不出現在「我的團」。若使用者改變任一決定，只影響 FR-001/FR-004/
  FR-024（訪客）、FR-025（加入）、FR-019（我的團），其餘規格不變。
- 快速比賽在資料層面沿用「團」這一類活動紀錄並加上快速類型的標記，而不是另建一套比賽
  紀錄；理由是計分、逐點紀錄、歸戶、分享卡、綁定戰績等全部既有功能都依附在「團內比賽」上，
  另立一套會讓戰績無法合併。使用者看不到這個內部結構。
- 快速比賽固定使用「手動安排」方式產生比賽（由使用者直接指定名單），不套用任何輪替或
  循環賽排程。
- 快速比賽的管理權限沿用既有的團管理機制，但不向使用者揭露 PIN：登入會員可透過既有
  「忘記 PIN」流程取回；訪客的管理權限只存在於當下的瀏覽器分頁／連結。
- 「一位會員同時只能在一個團活動」的既有規則同樣適用於快速比賽（FR-020），以免現有的
  歸戶與名單邏輯出現同一人同時在兩處的狀態。
- 收尾期限預設一天，放在系統共用設定中；不提供使用者自訂。
- 快速比賽只有一個場地，不提供「全部場地控制板」入口；既有的單一場地控制板已具備全部
  所需功能（含決勝分確認與詳細計分）。
- 已收尾的快速比賽沿用既有「已解散團」的最終排名保存方式，資料不刪除；帳號刪除（025）
  對快速比賽紀錄的處理與團內比賽相同。
- 不提供快速比賽的「開團管理頁」；使用者所有操作都在控制板完成。
- 沿用既有的身分與權限機制、即時同步機制、語系機制與時區規範。
