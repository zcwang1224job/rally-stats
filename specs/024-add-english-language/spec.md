# Feature Specification: 新增英文語系

**Feature Branch**: `024-add-english-language`

**Created**: 2026-09-14

**Status**: Draft

**Input**: User description: "新增英文語系"

## Clarifications

### Session 2026-09-14

- Q: 語言切換功能的開放對象與位置——僅限已登入會員透過既有個人設定切換，還是開放給所有使用者（含訪客、計分板/控制板等無需登入的畫面）？ → A: 開放給所有使用者，在共用導覽列提供隨時可見的語言切換入口；未登入時存在瀏覽器本機，登入後與會員語言偏好同步；計分板/控制板等沒有共用導覽列的頁面也 MUST 各自提供切換入口，不得因為缺少導覽列而沒有切換能力。
- Q: 「新增英文語系」的範圍是否包含後端寄出的交易性 Email（驗證信、密碼重設信）？ → A: 涵蓋——網頁畫面文字＋交易性 Email 皆需英文化，後端依會員當下的語言偏好決定寄出信件的語言版本。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 切換為英文並看到完整英文介面 (Priority: P1)

使用者將顯示語言切換為英文後，應用程式中原本以繁體中文顯示的文字（頁面標題、按鈕、表單標籤、提示訊息、錯誤訊息等）全面改為英文顯示，而不是只有部分畫面切換、其餘畫面仍停留在中文。

**Why this priority**：這是「新增英文語系」這個功能本身唯一的核心價值——如果切換後畫面仍大量停留在中文，這個功能就形同沒有做完，使用者會覺得「英文語系」是半成品。

**Independent Test**：可獨立測試——切換語言為英文後，任意瀏覽應用程式中至少 5 個不同功能的畫面（例如首頁、登入、建立揪團、計分板、個人設定），確認畫面文字皆為英文，沒有殘留的繁體中文字串。

**Acceptance Scenarios**:

1. **Given** 使用者將顯示語言切換為英文，**When** 使用者瀏覽應用程式中任一既有畫面，**Then** 該畫面上原本會顯示繁體中文文字的地方 MUST 改為顯示對應的英文文字。
2. **Given** 使用者將顯示語言切換為英文，**When** 某個操作觸發後端回傳的錯誤訊息（例如密碼輸入錯誤、通關密碼錯誤），**Then** 該錯誤訊息 MUST 以英文顯示，而不是顯示繁體中文或顯示原始錯誤代碼字串。
3. **Given** 使用者尚未切換過語言，**When** 使用者第一次開啟應用程式，**Then** 畫面 MUST 維持顯示既有的繁體中文（既有使用者的既有體驗不因這個新功能而被動改變）。
4. **Given** 使用者尚未登入（包含完全沒有帳號的訪客），**When** 使用者瀏覽應用程式中任一畫面，**Then** 畫面 MUST 提供一個隨時可見、不需登入即可使用的語言切換入口（Clarifications 2026-09-14）。
5. **Given** 使用者透過計分板或控制板連結開啟畫面（這類畫面沒有應用程式共用的導覽列），**When** 使用者想切換語言，**Then** 該畫面本身 MUST 提供自己的語言切換入口，MUST NOT 因為沒有共用導覽列而完全無法切換。
6. **Given** 會員的語言偏好目前是英文，**When** 系統因為該會員的操作寄出驗證信或密碼重設信，**Then** 該封信的標題與內文 MUST 以英文顯示（Clarifications 2026-09-14）。

### User Story 2 - 語言選擇會被記住，不需要每次重新設定 (Priority: P2)

使用者選擇英文之後，之後再次開啟應用程式（同一個瀏覽器）時，應用程式應自動維持顯示英文，不需要每次都重新選擇一次。

**Why this priority**：語言選擇若不能被記住，使用者每次重新整理或重新開啟頁面都要重選一次，體驗上等同没有真正做到「支援英文」，但這是在 US1（真正有英文內容可顯示）完成之後才有意義的加值能力。

**Independent Test**：可獨立測試——切換語言為英文後，重新整理頁面或重新開啟瀏覽器分頁再次進入應用程式，確認畫面仍維持英文顯示，不需要重新選擇。

**Acceptance Scenarios**:

1. **Given** 使用者已將顯示語言切換為英文，**When** 使用者重新整理頁面，**Then** 畫面 MUST 維持顯示英文，MUST NOT 重置回繁體中文。
2. **Given** 已登入會員已將顯示語言切換為英文，**When** 該會員換一台裝置登入同一個帳號，**Then** 該裝置 MUST 也顯示英文（延續既有「語言偏好」屬於會員帳號設定的既有能力）。
3. **Given** 尚未登入的訪客在這個瀏覽器將語言切換為英文，**When** 該訪客之後在同一個瀏覽器登入既有會員帳號，**Then** 系統 MUST 以該會員帳號既有的語言偏好設定為準顯示畫面（帳號設定優先於瀏覽器本機記住的訪客選擇），MUST NOT 讓兩者顯示不一致或閃爍切換。
4. **Given** 已登入會員將語言切換為英文，**When** 該會員登出，**Then** 該瀏覽器 MUST 維持顯示英文（登出不應該讓語言顯示退回預設值，避免使用者以為切換失敗）。
5. **Given** 尚未登入的訪客在這個瀏覽器將語言切換為英文，**When** 該訪客當場註冊一個全新的會員帳號（而非登入既有帳號），**Then** 這個新帳號的語言偏好初始值 MUST 直接採用註冊當下瀏覽器已選擇的語言（英文），MUST NOT 套用「未曾設定過即預設繁體中文」的既有預設規則，讓剛註冊、從未看過中文畫面的新用戶反而被切回中文。

---

### Edge Cases

- 使用者透過控制板連結（不需登入即可開啟的畫面）進入應用程式：這類畫面 MUST 各自提供自己的語言切換入口，MUST NOT 因為沒有應用程式共用的導覽列而變成只能停留在單一語言（FR-003a）。計分板連結是例外，見下方 2026-09-15 修正。
- 應用程式尚未涵蓋、未來才新增的功能：本功能範圍不包含尚未存在的畫面，僅涵蓋本功能實作當下應用程式已存在的全部畫面文字。
- 使用者切換語言後，畫面上顯示的日期／時間格式本身（例如「2026/09/14」的排列方式）不隨語言改變（見 Assumptions）。

### 後續修正（2026-09-15）

計分板連結（不需登入、供球員/觀眾在場邊查看比分的畫面）改為 MUST NOT 提供語言切換入口——移除 FR-003a 對計分板的適用範圍，理由：該畫面唯讀居多、觀眾非切換語言的主要使用情境，切換入口反而佔用「比分需可遠距離閱讀」的畫面空間（既有原則）。取而代之，計分板 MUST 自動採用該球場所屬揪團「建立者」當下的語言偏好設定顯示（無建立者記錄，例如訪客建團，則 MUST 顯示繁體中文，即系統預設值），不再受瀏覽器本機語言選擇或訪客切換影響。控制板（含多球場總覽）不受此修正影響，仍適用 FR-003a。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 提供英文作為可選擇的顯示語言，涵蓋應用程式目前已存在的**全部**畫面文字（不得僅翻譯部分功能、其餘維持中文）。
- **FR-002**: 系統 MUST 讓使用者能主動將顯示語言切換為英文，以及切換回繁體中文。
- **FR-003**: 系統 MUST 提供一個所有使用者（含未登入的訪客）都能看到、隨時可用的語言切換入口，不限於已登入會員的個人設定頁面內（Clarifications 2026-09-14）。
- **FR-003a**: 控制板（含多球場總覽）等不顯示應用程式共用導覽列的畫面，MUST 各自提供自己的語言切換入口，不得因為沒有共用導覽列而失去切換能力。計分板不適用本條，見下方 2026-09-15 修正與 FR-003d。
- **FR-003d**（2026-09-15 新增）：計分板 MUST NOT 提供語言切換入口，MUST 自動套用該球場所屬揪團「建立者」（`Group.created_by_member_id`）當下的 `language_preference`；該揪團無建立者記錄時 MUST 顯示系統預設語言（繁體中文）。
- **FR-003b**: 使用者未登入時選擇的語言 MUST 至少記在該使用者當下的瀏覽器中；使用者登入既有會員帳號後，MUST 改以該會員帳號既有的語言偏好設定為準顯示畫面（帳號設定優先於瀏覽器記住的訪客選擇，見 Assumptions 之說明）。
- **FR-003c**: 已登入會員透過這個全域切換入口變更語言時，MUST 同步更新該會員帳號既有的語言偏好設定（與「個人設定 -> 基本設定」頁面內的既有語言偏好選單顯示同一份設定值，兩處變更互相反映，不得出現兩份不同步的語言設定）。
- **FR-004**: 錯誤訊息（後端回傳的語意化錯誤代碼所對應的顯示文字）MUST 隨著目前選擇的語言顯示對應語言版本，不得因為切換語言而顯示原始錯誤代碼或退回中文。
- **FR-005**: 使用者尚未主動切換過語言時，系統 MUST 維持顯示既有的繁體中文，MUST NOT 自動依瀏覽器/裝置語言設定切換為英文（不得在使用者不知情的情況下改變既有體驗）。
- **FR-006**: 使用者選擇的語言 MUST 在同一瀏覽器的後續造訪中被記住，MUST NOT 每次重新整理或重新開啟頁面都恢復成預設語言。
- **FR-007**: 已登入會員選擇的語言，MUST 延續既有「語言偏好」會員設定能力（既有的個人設定功能），使該選擇在該會員登入的其他裝置上也生效。
- **FR-008**: 任何列出語言選項供使用者選擇的地方（既有「個人設定 -> 基本設定」的語言偏好選單、FR-003 新增的全域語言切換入口），MUST 針對清單中的每個語言選項顯示該語言自己對應的名稱（例如英文選項顯示「English」、繁體中文選項顯示「繁體中文」），不得所有選項都顯示同一個語言名稱。
- **FR-009**: 訪客在瀏覽器中選擇語言後，當場註冊一個全新的會員帳號時，該新帳號的語言偏好初始值 MUST 直接採用註冊當下瀏覽器已選擇的語言，MUST NOT 一律套用系統預設的繁體中文（US2 驗收情境 5）。
- **FR-010**: 系統寄出的交易性 Email（含帳號驗證信、密碼重設信）MUST 依收件會員當下的語言偏好設定，以對應語言顯示信件標題與內文（Clarifications 2026-09-14，US1 驗收情境 6）。

### Key Entities

- **顯示語言（Display Language）**：使用者目前選擇用來顯示應用程式介面的語言，可能的值目前為「繁體中文」與「英文」兩者之一。對已登入會員而言，這是既有會員帳號設定的一部分（跨裝置生效）；對未登入的訪客而言，這是存在該瀏覽器裡的暫時選擇（不跨裝置、不跨瀏覽器），登入後改以帳號設定為準（FR-003b）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者切換為英文後，抽測應用程式中至少 90% 的既有畫面文字（含錯誤訊息）皆正確顯示為英文，沒有殘留的繁體中文字串或原始錯誤代碼字串。
- **SC-001a**: 語言偏好為英文的會員觸發驗證信或密碼重設信時，100% 收到的信件標題與內文為英文，沒有殘留繁體中文內容。
- **SC-002**: 使用者切換語言（任一方向）後，2 秒內畫面文字更新為對應語言，不需要重新整理頁面。
- **SC-003**: 使用者選擇英文後，重新整理頁面或重新開啟應用程式，100% 的情況下畫面維持顯示英文，不會被重置回繁體中文。
- **SC-004**: 既有（本功能上線前就已經在使用應用程式的）使用者在未主動切換語言的情況下，100% 維持看到與本功能上線前完全相同的繁體中文畫面。

## Assumptions

- **翻譯範圍**：涵蓋本功能實作當下應用程式已存在的所有畫面文字與錯誤訊息，不包含尚未開發的功能；未來新增功能時，該功能本身的開發工作即需一併提供英文文字，不屬於本次範圍的持續性義務。
- **語言代碼與既有欄位相容**：延續既有會員設定中「語言偏好」欄位的既有可擴充設計（存為程式碼常數清單，非資料庫層級的固定選項），新增英文只需在既有清單中加入一個新值，不需要資料庫層級的變更。
- **日期／時間顯示格式不受語言影響**：切換語言僅改變文字內容，不改變日期／時間的排列格式（例如年月日的顯示順序），也不改變系統既有的時區顯示規則；這類格式一律維持應用程式既有的既定呈現方式。
- **不含新語言的在地化細節**：本次範圍僅止於文字翻譯本身，不包含針對英文使用者調整用詞以外的在地化細節（例如貨幣、度量單位——本應用程式本身也不涉及這些）。
- **不影響 Turnstile 等第三方元件的顯示語言**：任何由第三方服務提供、非本應用程式自行控制顯示語言的畫面元素，不在本功能範圍內。
- **登入時「帳號設定優先於瀏覽器訪客選擇」的理由**：訪客選擇與會員帳號設定兩者衝突時（例如訪客選了英文，登入的帳號卻儲存著預設的繁體中文），以帳號設定為準，行為簡單、可預期（「登入後以帳號為準」），不需要額外分辨「這個帳號的語言偏好是使用者曾經主動選過的值，還是從未變更過的預設值」；使用者若登入後仍想要英文，直接再切換一次即可，該次操作會依 FR-003c 存回帳號設定並從此持續生效，只需要多一次點擊，不構成重大體驗落差。
