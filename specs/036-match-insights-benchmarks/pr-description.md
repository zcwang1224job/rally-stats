# 036 對戰紀錄洞察：優缺點摘要、搭檔與對手戰績、團內比較、與好友比較

`feature/match-insights-benchmarks` → `ut`

## 這個 PR 做了什麼

個人對戰紀錄頁原本只有數字。這個 PR 補上三件事：**結論**（我的強項與弱點是什麼）、**對象**（我跟誰搭最順、老是輸給誰）、**基準**（我在團裡排第幾、和好友比如何）。全部由既有紀錄在查看當下推導。

| 使用者故事 | 內容 |
|---|---|
| US1 優缺點摘要 | 頁面前段列出強項、待加強、最近變化、對戰組合；每句附依據的數字，點擊跳到對應指標卡。規則式、可重現，後端只回傳規則代碼與數字，句子在語系檔。好友頁同樣呈現。 |
| US2 搭檔與對手戰績 | 新增搭檔戰績，對手戰績加上平均分差、排序與重點摘要。**列改為依球員身分彙總**。點某一列，整頁（清單、勝敗、儀表板、摘要）縮小到與他有關的比賽。 |
| US3 團內比較 | 選一個曾加入的團，看每項指標的團內平均、我的名次與比較人數。**匿名**。名列前後四分之一的指標併入摘要。 |
| US4 與好友比較 | 好友戰績頁的「與我比較」：23 項指標並排、標示較佳的一方，以及兩人互為對手／搭檔的紀錄。 |

## 部署

**沒有 migration、沒有新套件、沒有新環境變數。** 新回應欄位皆具預設值、新 query 參數皆選填，前後端任一先部署都相容；回滾沒有資料面的影響。

## 刻意的行為變更

- **對手戰績的列由「暱稱」改為「球員身分」切分**（`m:<member_id>`／`r:<roster_entry_id>`）。同一位會員在不同團用不同暱稱 → 合併為一列；不同人同暱稱 → 分開。最具體的影響：帳號刪除後暱稱一律是「Deleted User」，過去所有已刪除帳號的對手會被併成一列，現在各自獨立。同一份資料的列數因此可能與上線前不同。014 的團歷史頁沿用同一個建構函式，列的切分同步改變，但回應仍只有原本五個欄位。
- 對戰紀錄頁的 `hasActiveFilters` 修正：原本計算的是篩選物件的「鍵」數，而 `load()` 總是建立完整物件（值多為 `undefined`），所以第一次載入後恆為真——「清除篩選」鈕一直顯示。改為計算有值的項目。US3 的摘要來源切換依賴這個判斷。

## 順帶修正的既有缺陷

`verify_ever_group_member()` 以 `scalar_one_or_none()` 查名單列，而 `join_group()` 每次加入都新增一列——**離團後重新加入的會員有兩列，會拋 `MultipleResultsFound` → 500**。影響 014 既有的兩支端點（團歷史、單場詳情），US3 也重用這個檢查。先寫了會失敗的迴歸測試確認，再改為 `.limit(1)`。

## 授權邊界

- 三支新端點（`/members/me/benchmark-groups`、`/members/me/group-benchmark`、`/members/{member_id}/match-comparison`）皆 `require_verified_member`，皆唯讀、不寫入、不通知。
- 團內比較沿用 014 已定案的「曾為該團正式成員」（含已離開、已被踢除、團已解散），每次請求判定；從未加入的團與不存在的團同為 403。
- **匿名由回應結構保證**：`GroupBenchmarkMetric` 沒有任何可放他人資料的欄位，他人的個別數值只存在於伺服器端的運算過程。契約測試掃描 `group`＋`metrics`＋團內來源的敘述。合併版摘要中檢視者**本人的**對戰組合敘述會出現搭檔／對手暱稱——那是他自己的對戰紀錄，與儀表板回應逐字相同。
- 與好友比較沿用 023 的 `_resolve_viewable_member()` 四段檢查；檢視者本人的分享設定無關。好友頁**不提供**團內比較。
- 不新增任何隱私設定。

## 實作過程中推翻的三個原設計（規格已同步）

1. **自我對比的基準。** 分析階段建議的「逐場加權全場得分率」被零偏差模擬測試證明比原本的合併相除**更差**（發球 −1.5 個百分點 vs. +1.1）。原因是漏了單場內的效應：發球分就是「贏了上一分之後的那一分」。以三種強度的合成球員實測後定案：發球類用條件期望 `(得分−1)÷(總分−1)`（偏差 ±0.06）；局末用合併全場得分率；**平手時得分率與領先／落後同列排除**（任何基準皆有 0.9–1.7 個百分點的固定偏差）。
2. **四分之一的切點。** 規格原寫「無條件進位」，與同段的例子矛盾（5 人會取 2 名）。改為無條件捨去。
3. **並列與四分之一。** 實機截圖發現 7 人中多人賽末點兌現率同為 100%，全被列為「強項」。改為計入並列人數：與我同名次或更好的人數不超過四分之一才算。
