# Feature Specification: 好友戰績檢視入口

**Feature Branch**: `023-view-friend-match-records`

**Created**: 2026-09-14

**Status**: Draft

**Input**: User description: "會員專區 -> 好友，點擊好友/每個好友新增一個檢視按鈕，按下去後可以檢視好友的戰績紀錄頁面。"

## Clarifications

### Session 2026-09-14

- Q: 好友透過這個新入口看到的戰績，是完整跨團戰績（沿用 022 現有行為），還是僅限兩人曾經同團出現過的比賽？ → A: 完整跨團戰績（沿用 022 現有行為，好友看到的和「我的戰績」內容範圍相同）
- Q: 好友檢視戰績時，被檢視方是否會收到通知？ → A: 不通知：好友檢視戰績時，被檢視方不會收到任何通知或紀錄

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 從好友列表檢視好友戰績 (Priority: P1)

已驗證的會員進入「會員專區 -> 好友」的好友列表，在任一好友項目旁點擊「檢視戰績」，系統導向該好友的戰績檢視頁面，顯示該好友的對戰紀錄與彙總戰績統計；若該好友目前未開放好友查看戰績，系統清楚告知原因，而非顯示空白或令人困惑的畫面。

**Why this priority**：這是本功能唯一被要求的核心能力——「新增檢視按鈕、按下去後可以檢視好友的戰績紀錄頁面」。沒有這個功能，整個 feature 就不存在；同時涵蓋「能看」與「不能看時要清楚告知」兩種結果，才是完整可用的單一能力，缺一不可。

**Independent Test**：可獨立測試——以會員 A 登入，好友列表中已有好友 B；點擊 B 旁的「檢視戰績」，驗證導向 B 的戰績頁面並顯示對戰紀錄與統計；將 B 的隱私設定改為不開放好友查看戰績後重新點擊，驗證改為顯示清楚的不公開提示。

**Acceptance Scenarios**:

1. **Given** 會員 A 與會員 B 已是好友關係，且 B 目前允許好友查看戰績，**When** A 在好友列表點擊 B 旁的「檢視戰績」，**Then** 系統導向 B 的戰績檢視頁面，顯示 B 的對戰紀錄列表（依時間新到舊排序）與彙總戰績統計（總場次、勝場、敗場、勝率）。
2. **Given** 會員 A 與會員 B 已是好友關係，但 B 目前已將「好友可查看我的戰績」設為關閉，**When** A 點擊 B 旁的「檢視戰績」，**Then** 系統 MUST 清楚顯示「B 已將戰績設為不公開」之類的明確提示，MUST NOT 顯示空白頁面或讓 A 誤以為 B 沒有任何對戰紀錄。
3. **Given** 會員 A 正在檢視好友 B 的戰績頁面，**When** B 在同一時間將「好友可查看我的戰績」改為關閉，**Then** A 之後任何會重新向伺服器要資料的操作（例如換頁、重新整理）MUST 顯示與情境 2 相同的不公開提示，MUST NOT 繼續呈現彷彿仍有權限的資料。
4. **Given** 會員 A 與會員 B 已解除好友關係，**When** A 嘗試重新開啟先前曾檢視過的 B 的戰績頁面，**Then** 系統 MUST 拒絕顯示戰績內容，並提示需先成為好友才能查看。
5. **Given** 好友 B 目前尚無任何對戰紀錄（例如剛註冊的新會員），**When** A 檢視 B 的戰績頁面，**Then** 系統 MUST 顯示清楚的「尚無對戰紀錄」空狀態，MUST NOT 呈現得像發生錯誤。
6. **Given** 好友列表筆數眾多、部分好友暱稱很長，**When** A 在行動裝置瀏覽好友列表，**Then** 「檢視戰績」的操作入口 MUST 仍清楚可見且可點擊，不因畫面寬度而被遮擋或難以點按。

---

### User Story 2 - 從好友戰績列表查看單場比賽詳情 (Priority: P2)

會員在好友的戰績列表中點擊任一場對戰紀錄，可以查看該場比賽的詳細資訊（例如雙方隊伍成員、比分、比賽時間）。

**Why this priority**：戰績列表本身（US1）已提供核心價值；點進單場比賽詳情是既有「檢視自己戰績」體驗中已存在的加值能力，延伸到好友戰績檢視時能讓體驗一致，但並非「有沒有這個功能就完全無法使用」的必要條件，故排序在 US1 之後。

**Independent Test**：可獨立測試——在好友 B 的戰績列表中點擊任一筆對戰紀錄，驗證顯示該場比賽的隊伍組成、比分與比賽時間等詳細資訊。

**Acceptance Scenarios**:

1. **Given** 會員 A 正在檢視好友 B 的戰績列表且列表中至少有一筆對戰紀錄，**When** A 點擊其中一筆，**Then** 系統顯示該場比賽的詳細資訊（雙方隊伍成員、比分、比賽時間）。
2. **Given** 會員 A 與好友 B 之間已不再符合檢視資格（解除好友關係或 B 已關閉分享），**When** A 嘗試查看先前開啟過的某場比賽詳情，**Then** 系統 MUST 拒絕顯示，並提示原因，與 US1 情境 2、4 的提示邏輯一致。

---

### Edge Cases

- 會員嘗試直接以網址列輸入其他會員的識別碼存取戰績檢視頁面（未經由好友列表點擊）：系統 MUST 套用與點擊「檢視戰績」完全相同的資格檢查（是否為好友、對方是否開放分享），不得因為存取路徑不同而放寬或收緊權限判斷。
- 「檢視戰績」入口 MUST 僅出現在好友列表中已成立好友關係的對象上，本功能不擴大好友列表原本的涵蓋範圍（不會讓非好友、待處理邀請中的對象出現此按鈕）。
- 會員嘗試檢視自己：好友列表本身不會列出自己，故此情境不適用。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 在好友列表的每一位好友項目旁提供「檢視戰績」的操作入口。
- **FR-002**: 會員點擊「檢視戰績」後，系統 MUST 導向該好友的戰績檢視頁面。
- **FR-003**: 當目標好友目前允許好友查看戰績時，戰績檢視頁面 MUST 顯示該好友的對戰紀錄列表（依時間新到舊排序）與彙總戰績統計（至少包含總場次、勝場、敗場、勝率），範圍為該好友「曾經加入過的所有團」之完整跨團戰績，MUST NOT 僅限縮於檢視者與該好友曾經同團的部分。
- **FR-004**: 當對戰紀錄筆數超過單頁可顯示數量時，系統 MUST 提供分頁瀏覽的方式。
- **FR-005**: 當目標好友目前已將「好友可查看我的戰績」設為關閉時，系統 MUST 以明確文字告知會員此好友已將戰績設為不公開，MUST NOT 顯示空白頁面或令人誤解為沒有資料。
- **FR-006**: 會員在戰績列表中點擊任一場對戰紀錄時，系統 MUST 顯示該場比賽的詳細資訊（至少包含雙方隊伍成員、比分、比賽時間）。
- **FR-007**: 當會員與目標對象之間不符合檢視資格時（尚未成立好友關係、已解除好友關係，或目標已關閉分享），系統 MUST 拒絕顯示任何戰績內容或比賽詳情，並提示相對應的原因，MUST NOT 因為之前曾經檢視過而繼續顯示資料。
- **FR-008**: 上述資格檢查 MUST 以會員當下實際點擊/請求當下的好友關係與對方隱私設定為準，MUST NOT 使用先前載入時快取的資格判斷結果。
- **FR-009**: 「檢視戰績」操作入口 MUST 僅出現在好友列表中已成立好友關係的對象上。
- **FR-010**: 當目標好友尚無任何對戰紀錄時，戰績檢視頁面 MUST 顯示明確的「尚無對戰紀錄」空狀態，MUST NOT 呈現得像發生錯誤或載入失敗。
- **FR-011**: 好友檢視戰績（含列表與單場比賽詳情）時，系統 MUST NOT 通知或以任何形式告知被檢視方「誰檢視了、檢視了幾次」（Clarifications 2026-09-14）。

### Key Entities

本功能不新增資料實體，僅新增一個檢視入口與檢視頁面，呈現既有的下列實體（沿用既有的好友關係、隱私設定、對戰紀錄資料模型，定義不變）：

- **好友關係（Friend Relationship）**：既有實體，用於判斷會員是否有資格檢視目標對象的戰績。
- **隱私設定（Privacy Setting）**：既有實體中「是否允許好友查看戰績」這一項設定，決定戰績內容是否可被顯示。
- **對戰紀錄（Match Record）與彙總戰績統計（Match Statistics）**：既有實體，範圍為該會員「曾經加入過的所有團」之完整跨團對戰紀錄與統計（與既有「我的戰績」頁面範圍相同），本功能將其呈現對象從「僅限本人」擴充為「本人主動授權查看的好友，透過此檢視入口存取」；MUST NOT 因為檢視者與該會員是否曾同團而縮限顯示範圍（Clarifications 2026-09-14）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 已有好友的會員能在好友列表點擊「檢視戰績」後，2 秒內看到該好友的戰績頁面內容或明確的不公開提示（不含網路延遲）。
- **SC-002**: 目標好友開放分享時，100% 的檢視請求皆能成功顯示戰績列表與彙總統計。
- **SC-003**: 目標好友已設為不公開、或會員與目標已非好友關係時，100% 的檢視嘗試皆會看到清楚易懂的拒絕提示，且提示內容能讓會員理解「為什麼看不到」。
- **SC-004**: 使用行動裝置瀏覽好友列表與好友戰績檢視頁面時，操作入口、列表、分頁皆可正常操作，不需要橫向捲動整個頁面。

## Assumptions

- **戰績檢視頁面的篩選能力**：本次範圍僅要求依時間排序＋分頁瀏覽好友的完整對戰紀錄，不包含依對手／日期／比分等條件篩選的進階功能（既有「我的戰績」頁面已有的進階篩選）；若未來有實際需求，屬於獨立的功能擴充。
- **彙總統計呈現範圍**：僅要求總場次、勝場、敗場、勝率四項基本統計，不包含各輪次勝率趨勢圖、對戰對象排行等進階圖表；若未來有實際需求，屬於獨立的功能擴充。
- **「戰績」的定義與範圍**：延續會員個人設定功能既有的定案範圍，同時涵蓋逐場對戰紀錄明細與彙總統計數據兩者，兩者受同一項隱私設定共同控管，不可分開授權；範圍為完整跨團戰績，不因檢視者與好友是否同團而縮限（已於 Clarifications 段落確認，見 FR-003）。
- **不改變好友關係與隱私設定本身**：本功能純粹新增「檢視」入口與頁面，不涉及好友關係的建立/解除邏輯、也不涉及隱私設定開關本身的異動，兩者皆沿用既有能力。
- **「檢視戰績」入口的顯示邏輯**：入口對所有已成立好友關係的對象一律顯示，不會因為預先得知對方隱私設定而選擇性隱藏——實際是否能檢視由點擊後系統當下的判斷結果決定（因此才需要 FR-005 明確的不公開提示，而非以隱藏按鈕取代提示）。
- **被檢視方不會被通知**：已於 Clarifications 段落確認為不通知（見 FR-011），「允許好友查看我的戰績」這個開關本身即視為授權，開啟後即代表願意被好友隨時查看，不需要逐次告知。
