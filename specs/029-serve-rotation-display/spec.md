# Feature Specification: 計分板發球站位顯示

**Feature Branch**: `029-serve-rotation-display`

**Created**: 2026-09-15

**Status**: Draft

**Input**: User description: "比賽一開始由系統隨機指派發球方，並根據正規發球順序的規則，在得分板上顯示正確的站位與發球人，顯示方式人員暱稱分別放置在計分板四個角落代表各自站位"

## Clarifications

### Session 2026-09-15

- Q: 雙打比賽時，系統隨機指定「發球隊伍」之後，該隊兩位隊員中由誰擔任第一位發球者，要怎麼決定？ → A: 完全隨機挑一位——系統從發球隊伍的兩位隊員中隨機抽一位當第一位發球者，跟指定發球隊伍一樣完全交給系統決定，不需要額外資料或人工介入。
- Q: 計分員用既有的「-1」修正比分時，發球者與站位顯示該怎麼處理？ → A: 依修正後比分即時重算——站位永遠是「目前比分」的函式，-1 修正後畫面立刻重新算出對應的正確站位。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 觀看計分板即可看出目前發球者與站位 (Priority: P1)

球員或旁觀者站在球場邊看計分板時，畫面上四個角落分別標示雙方球員（單打為兩位、雙打為四位）目前應站立的位置，並清楚標示其中誰是目前的發球者，不需要另外詢問或自行推算。

**Why this priority**: 這是本功能唯一直接被使用者看到的價值——沒有這個顯示，隨機指派發球方、計算發球規則都沒有意義。

**Independent Test**: 開啟一場已在進行中、比分不為 0:0 的比賽的計分板連結，確認四個角落是否各自顯示正確球員暱稱，以及能否一眼看出誰在發球。

**Acceptance Scenarios**:

1. **Given** 一場雙打比賽正在進行中，**When** 使用者開啟該球場的計分板連結，**Then** 畫面四個角落 MUST 分別顯示四位球員各自的暱稱，且其中發球者的位置 MUST 有額外視覺標示（非僅靠顏色）指出「這位在發球」。
2. **Given** 一場單打比賽正在進行中，**When** 使用者開啟該球場的計分板連結，**Then** 畫面 MUST 只在對角線的兩個角落顯示發球者與接發球者的暱稱，另外兩個角落 MUST 保持空白。
3. **Given** 計分板正顯示目前的發球站位，**When** 該場比賽得一分（比分更新），**Then** 站位與發球者顯示 MUST 依照正規發球規則自動更新為得分後應有的正確狀態，且不需要重新整理頁面。

---

### User Story 2 - 比賽開始時系統自動決定首位發球方 (Priority: P2)

一場新比賽由「尚未開始」轉為「進行中」時，系統自動隨機決定哪一方先發球，取代目前完全沒有發球方紀錄、球員需自行喬定或用擲硬幣等場外方式決定的情況。

**Why this priority**: 是 User Story 1 顯示內容的前提資料來源，但即使沒有畫面呈現，這個「開賽即隨機指定」的行為本身也可以獨立驗證。

**Independent Test**: 讓一場比賽的狀態從「排隊中/等待中」轉為「進行中」，確認系統已經指定出一個發球方（與必要時的發球者），且同一場比賽之後不會再重新隨機指定。

**Acceptance Scenarios**:

1. **Given** 一場比賽剛從等待狀態變成進行中、雙方比分皆為 0，**When** 系統完成該場比賽的開賽處理，**Then** 系統 MUST 已隨機決定其中一隊為首位發球方。
2. **Given** 首位發球方已經隨機決定完成，**When** 任何人再次查詢這場比賽的發球狀態，**Then** 結果 MUST 與第一次決定的結果相同（不會每次查詢都重新抽一次）。

---

### User Story 3 - 多人同時查看時資訊一致且即時 (Priority: P3)

同一場比賽的計分板連結可能同時被多人（球員本人、場邊觀眾、行動裝置與平板）打開，且比分可能透過控制板或計分板本身即時更動；所有人看到的發球者與站位資訊必須彼此一致、並跟著比分即時更新。

**Why this priority**: 屬於既有計分板即時同步能力（比分本身已支援多人同時觀看即時更新）的延伸，價值明確但不影響前兩個使用者故事的核心可用性，可以晚一點再處理。

**Independent Test**: 用兩個不同裝置同時開啟同一場比賽的計分板連結，在其中一個裝置為該比賽加分後，確認另一個裝置的發球站位顯示在不需手動整理頁面的情況下同步更新為一致的結果。

**Acceptance Scenarios**:

1. **Given** 兩個裝置同時開啟同一場進行中比賽的計分板，**When** 其中一方得分，**Then** 兩個裝置 MUST 在得分事件送達後顯示相同的發球者與站位，不會出現不一致的情形。
2. **Given** 一個裝置在比賽進行到一半時才第一次開啟計分板連結，**When** 該連結載入完成，**Then** 顯示的發球站位 MUST 與其他一路開著、持續同步的裝置目前看到的結果相同（不是從第一分開始重新播放）。

---

### Edge Cases

- 比賽尚未開始（沒有進行中的比賽）或已經結束（completed/abandoned）時，計分板 MUST NOT 顯示發球站位資訊——沒有正在進行的發球可以顯示。
- 比分進入平分／續分（deuce）等雙方比分交錯上升的情況時，發球站位仍必須正確依照「目前發球方比分為奇數或偶數」切換左右發球區，不能因為比分差距縮小或交替變化而算錯。
- 計分員使用既有的「-1」修正比分時，發球站位顯示 MUST 依修正後的比分立即重新計算（Clarifications 2026-09-15），因此修正比分後畫面上的站位可能與修正前不同，這是預期行為。
- 訪客/觀眾中途才開啟計分板連結（比賽已經進行一段時間、比分不是 0:0）時，畫面 MUST 能直接顯示當下正確的站位，而不是要求先重播整場比賽的得分過程。
- 該球場的計分板連結被重新產生（既有的連結失效重發功能）後，若比賽仍在進行中，新連結開啟時的發球站位顯示 MUST 與失效前一致，不受連結本身重新產生影響。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 在每場比賽（match）由「尚未開始/佇列中」轉為「進行中」時，隨機指定其中一隊（team A 或 team B）為該場比賽的首位發球方。
- **FR-002**: 雙打比賽時，系統 MUST 從已隨機指定的發球隊伍之兩位隊員中，完全隨機挑選一位擔任該場比賽的第一位發球者（Clarifications 2026-09-15）。
- **FR-003**: 系統 MUST 依照正規羽球發球順序規則（單打與雙打規則不同，且發球方目前比分為奇數或偶數決定其應站右側或左側發球區），根據比賽目前比分與發球歷程，持續計算出「目前發球者」以及「雙方（單打 2 位、雙打 4 位）球員各自目前應站立的位置」。
- **FR-004**: 計分板畫面 MUST 將 FR-003 計算出的站位結果對應到畫面四個角落，並在對應角落顯示該位置球員的暱稱。
- **FR-005**: 計分板畫面 MUST 以文字或圖示等非純顏色的視覺方式，清楚標示四位（或單打時兩位）球員中目前的發球者是誰。
- **FR-006**: 單打比賽時，計分板 MUST 只在對角線的兩個角落顯示球員暱稱（發球者與接發球者所在位置），另外兩個角落 MUST 保持空白，不得顯示不存在的第三、四位球員。
- **FR-007**: 當比賽沒有正在進行中的對局（尚未開始或已結束）時，計分板 MUST NOT 顯示發球站位資訊。
- **FR-008**: 同一場比賽的發球者與站位資訊，在同一時間點對所有開啟該比賽計分板連結的人 MUST 呈現一致的結果，不因裝置或開啟時間不同而不同。
- **FR-009**: 比分透過既有加分（+1）動作變動時，發球者與站位顯示 MUST 依照 FR-003 的規則即時更新，不需要重新整理頁面。
- **FR-010**: 計分員使用既有「-1」動作修正比分時，發球者與站位顯示 MUST 依「修正後的比分」立即重新計算並更新對應站位（Clarifications 2026-09-15）。
- **FR-011**: 中途才開啟計分板連結、或計分板連結被重新產生後才第一次載入的情況下，系統 MUST 能直接顯示比賽當下正確的發球站位，不需要重新播放該場比賽從第一分以來的完整得分過程才能得到正確結果。

### Key Entities *(include if feature involves data)*

- **發球狀態（Serve State）**：附屬於一場正在進行中的比賽（Match），記錄「目前發球隊伍」「雙打時目前發球者是哪一位球員」，並可依此與目前比分推導出雙方球員（單打 2 位、雙打 4 位）各自目前應站立的位置。一場比賽開始時建立一次，隨該場比賽的比分變化而更新，比賽結束後不再有意義。
- **站位（Station）**：計分板畫面上四個角落之一，對應到球場上的一個發球/接發球位置；每個站位在某一時間點對應到 0 或 1 位球員（單打時有兩個站位保持空缺）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% 新開始進行中的比賽，計分板在比賽轉為進行中的同時即顯示發球者與站位，不需要任何人額外操作或設定。
- **SC-002**: 旁觀者看一眼計分板的四個角落，不需要另外詢問球員或計分員，就能正確指出「現在該由誰發球」。
- **SC-003**: 針對任意一組單打或雙打比分序列，計分板顯示的發球站位皆符合正規羽球發球規則，不會出現「目前顯示的發球方站位與比分不符」的情形。
- **SC-004**: 同一場比賽的發球者與站位資訊，在多個同時開啟該計分板連結的裝置之間，於每次得分後於使用者可感知的極短時間內（與既有比分同步的即時性一致）保持一致，不出現不同裝置顯示不同發球者的情形。

## Assumptions

- 「正規發球順序的規則」採用國際羽球總會（BWF）現行單打／雙打發球輪轉規則作為依據；規則中除本規格已列出的「發球方比分奇偶決定左右發球區」「發球者與接發球者站對角線」等重點之外的細節（例如非發球/非接發球的兩位隊友於各次發球之間如何延續其站位），實作與規劃階段依此國際標準規則決定，不在本規格逐條列出。
- 本功能僅套用於「計分板」（scoreboard，courtToken 連結開啟的頁面）；控制板（control-panel）、多球場總覽（all-courts）等其他頁面是否同步顯示發球站位，不在本次範圍內，維持現狀不顯示。
- 現行資料模型中一場比賽（Match）沒有「分成多局（games）」的概念，只有單一連續比分直到比賽結束；本功能比照現狀，只在每場比賽開始時重新隨機指定一次發球方，不處理「同一場比賽切分成多局、每局重新指定發球方」的情境。
- 現有的比分即時同步機制（多裝置同時觀看計分板、比分變動即時反映）足以承載發球站位變更所需的即時性，不需要另外設計全新的即時通知種類；實作方式留待規劃階段決定。
- 比分修正（-1）在實際使用上遠比正常得分（+1）少見，主要用於修正記錄失誤等例外情境。
