# Feature Specification: 對戰紀錄逐點得失分球員與落點資訊、球員得失分統計

**Feature Branch**: `032-match-record-scoring-stats`

**Created**: 2026-09-16

**Status**: Draft

**Input**: User description: "在對戰紀錄中，每一筆比賽的每一個加分紀錄，顯示得失分球員（如果有設定的話），點下去之後，會顯示羽球落點資訊。並且該比賽的整體統計，要統計每位球員的得失分統計。"

## Clarifications

### Session 2026-09-16

- Q: 點擊已記錄落點的加分紀錄後，落點資訊要用什麼方式呈現？ → A: 在同一個比賽詳情對話框內原地展開（點擊該筆紀錄即在其下方展開球場示意圖與落點標記；再次點擊同一筆可收合，點擊另一筆則切換展開對象），不另外疊加新的對話框。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 逐點紀錄顯示得失分球員 (Priority: P1)

我是會員或訪客，正在查看「對戰紀錄」中某場已開啟詳細計分模式的比賽詳情（逐筆加減分紀錄清單，016 既有功能）。對於每一筆有記錄「得分球員」與「失分球員」的加分紀錄，我想直接在該筆旁邊看到是哪兩位球員，不必額外操作。

**Why this priority**：這是本功能的核心價值——比賽當下的「詳細計分模式」已經記錄了每一分的得分/失分球員與落點，但目前對戰紀錄完全沒有呈現這份資料，等於白白記錄卻沒有回饋給使用者。沒有這一步，後續的落點細節與球員統計都無從談起。

**Independent Test**：任選一場已開啟詳細計分模式、且至少有一筆加分紀錄選擇了得分/失分球員的比賽，點進其對戰紀錄詳情，可獨立驗證：每一筆有記錄球員的加分紀錄旁，都正確顯示當時選擇的得分球員與失分球員暱稱；沒有記錄球員的加分紀錄（例如當時按下「跳過」），則不顯示任何球員資訊。

**Acceptance Scenarios**:

1. **Given** 一場已完成、開啟詳細計分模式的比賽，其中某一筆加分紀錄當時記錄了得分球員與失分球員, **When** 使用者查看這場比賽的逐點紀錄, **Then** 系統 MUST 在該筆加分紀錄旁顯示得分球員與失分球員的暱稱。
2. **Given** 同一場比賽中，另一筆加分紀錄當時只選了得分球員、沒有選失分球員（或反之）, **When** 使用者查看逐點紀錄, **Then** 系統 MUST 只顯示當時確實選擇的那一位球員，不得虛構或省略另一位造成誤解。
3. **Given** 一場已開啟詳細計分模式的比賽中，某一筆加分紀錄當時被「跳過」（未選擇任何球員或落點）, **When** 使用者查看逐點紀錄, **Then** 該筆紀錄旁 MUST 不顯示任何球員資訊，維持與扣分紀錄相同的原本樣式。
4. **Given** 一場比賽從未開啟過詳細計分模式（僅有基本加減分紀錄）, **When** 使用者查看其逐點紀錄, **Then** 畫面 MUST 與功能上線前完全一致，不出現任何球員標示或空白佔位。

### User Story 2 - 點擊查看該分的羽球落點 (Priority: P1)

我是同一位使用者，看到某筆加分紀錄已經顯示得分/失分球員後，我想點擊這筆紀錄，看到這一分實際落在球場的哪個位置，跟計分當下畫的球場示意圖一樣直覺。

**Why this priority**：得失分球員只回答「誰」，落點才回答「怎麼發生的」（界內外、前中後場等）——這是詳細計分模式相對於普通計分最有價值、也是使用者最想回頭查看的資訊，因此與 US1 並列最高優先。

**Independent Test**：在已顯示得分/失分球員的加分紀錄上點擊，可獨立驗證：該筆紀錄原地（同一個比賽詳情畫面內，不彈出新視窗、不跳轉頁面）展開一個球場示意圖，並在正確的相對座標上標示出這一分記錄下來的落點；點擊沒有記錄球員（也就沒有落點）的加分紀錄或扣分紀錄則沒有反應，或明確不可點擊。

**Acceptance Scenarios**:

1. **Given** 一筆加分紀錄已顯示得分/失分球員, **When** 使用者點擊這筆紀錄, **Then** 系統 MUST 在該筆紀錄下方原地展開這一分記錄下來的羽球落點座標（以球場示意圖呈現，與計分當下的畫面風格一致），不得另外彈出新的對話框或跳轉頁面。
2. **Given** 某筆加分紀錄有記錄得分/失分球員、但當時沒有標示落點（只選了球員、跳過落點）, **When** 使用者點擊這筆紀錄, **Then** 系統 MUST 在原地展開處明確顯示「未記錄落點」，而非顯示錯誤的座標或空白圖。
3. **Given** 一筆加分紀錄沒有顯示任何球員資訊（跳過或非詳細計分模式）, **When** 使用者嘗試點擊, **Then** 系統 MUST NOT 呈現任何落點資訊或誤導性的互動效果。
4. **Given** 使用者已點開某筆加分紀錄的落點資訊, **When** 使用者再次點擊同一筆紀錄, **Then** 系統 MUST 收合該筆已展開的落點資訊。
5. **Given** 使用者已點開某筆加分紀錄的落點資訊, **When** 使用者點擊另一筆同樣有記錄落點的加分紀錄, **Then** 系統 MUST 收合原本展開的那一筆，改為展開新點擊的這一筆（同時間至多展開一筆）。

### User Story 3 - 整場比賽的球員得失分統計 (Priority: P2)

我是同一位使用者，看完逐點紀錄後，我想在比賽詳情畫面看到一個總覽：這場比賽裡每一位球員總共「得了幾分」、「造成對方失了幾分（自己的失誤或被得分）」，不必自己從落點紀錄一筆一筆數。

**Why this priority**：這是把逐點資料「彙整成洞見」的加值功能，價值建立在 US1/US2 已經把逐點資料攤開之上，因此優先度次於前兩者，但仍是使用者明確要求的核心產出。

**Independent Test**：在一場已有多筆記錄得分/失分球員的比賽詳情畫面，可獨立驗證：畫面出現雙方所有參賽球員的得失分統計，每位球員的「得分次數」與「造成失分次數」數字，與該場比賽所有加分紀錄中該球員被記錄為得分球員/失分球員的實際次數逐筆核對一致。

**Acceptance Scenarios**:

1. **Given** 一場比賽有多筆加分紀錄記錄了得分/失分球員, **When** 使用者查看比賽詳情, **Then** 系統 MUST 顯示雙方所有參賽球員各自的「得分次數」與「造成失分次數」統計。
2. **Given** 某位球員在整場比賽中一次都沒被記錄為得分或失分球員（例如搭檔的每一分都由對方或隊友觸發記錄）, **When** 使用者查看統計, **Then** 該球員 MUST 仍出現在統計中，數字明確顯示為 0，而非從清單中省略。
3. **Given** 一場比賽完全沒有任何一筆加分紀錄記錄過得分/失分球員（非詳細計分模式，或詳細計分但每一分都跳過）, **When** 使用者查看比賽詳情, **Then** 系統 MUST 以清楚的提示（例如「此比賽沒有球員得失分紀錄」）取代統計區塊，不得顯示全部為 0 的統計表造成「資料存在但都是 0」的誤解。
4. **Given** 比賽中有加分紀錄被「跳過」（未記錄球員）而其餘紀錄有記錄球員, **When** 使用者查看統計, **Then** 統計數字 MUST 只計入確實記錄了球員的加分紀錄，跳過的加分紀錄不計入任何個人數字（但依然計入隊伍總比分，此為既有行為不受影響）。

### Edge Cases

- 比賽扣分（-1 修正）本身從不記錄得分/失分球員或落點，逐點紀錄清單中的扣分列維持現狀，不受本功能影響。
- 一場比賽在過程中才被管理者開啟「詳細計分模式」：開啟前的加分紀錄沒有球員/落點資料，開啟後才有——同一場比賽的逐點清單中，兩種紀錄並存，各自依照有無資料正確顯示（有資料的顯示、沒有的不顯示），不需要額外的「部分開啟」提示。
- 對戰紀錄清單目前有三個既有入口（某團對戰紀錄、會員個人跨團對戰紀錄、某團歷史戰績），三者共用同一個比賽詳情彈出視窗——本功能 MUST 同時套用到這三個入口，不得只有其中之一支援。
- 訪客（Guest）與會員身份看到的球員暱稱、落點與統計資訊 MUST 與目前「對戰紀錄」既有的顯示權限一致，本功能不新增、也不放寬任何原本沒有的檢視權限。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 在比賽的逐點加減分紀錄中，針對已記錄得分球員與/或失分球員的每一筆加分紀錄，於該筆旁顯示已記錄的球員暱稱；只記錄其中一位時，僅顯示已記錄的那一位。
- **FR-002**: 對於沒有記錄任何球員的加分紀錄（例如當時選擇「跳過」，或該比賽並未開啟詳細計分模式），系統 MUST NOT 顯示球員資訊，且畫面 MUST 與功能上線前一致。
- **FR-003**: 系統 MUST 讓使用者能點擊已顯示球員資訊的加分紀錄，在同一個比賽詳情畫面內、該筆紀錄下方原地展開這一分記錄下來的羽球落點座標，不得另外彈出新的對話框或跳轉頁面。
- **FR-004**: 已顯示球員資訊、但當時未記錄落點座標的加分紀錄，點擊後系統 MUST 在原地展開處明確顯示「未記錄落點」，不得顯示錯誤或空白座標。
- **FR-004a**: 同一時間 MUST 至多只有一筆加分紀錄處於展開狀態；點擊已展開的那一筆將其收合，點擊另一筆有落點資料的紀錄則切換展開對象。
- **FR-005**: 扣分紀錄（delta 為 -1 的修正）MUST 永遠不顯示球員資訊或落點資訊，維持現有呈現方式。
- **FR-006**: 系統 MUST 在比賽詳情畫面提供一份「球員得失分統計」，列出這場比賽雙方全部參賽球員各自的「得分次數」與「造成對方失分次數」。
- **FR-007**: 「球員得失分統計」的數字 MUST 只計入確實記錄了得分球員/失分球員的加分紀錄；未記錄球員的加分紀錄不得計入任何個人數字，但仍計入隊伍總比分（既有行為不變）。
- **FR-008**: 若整場比賽沒有任何一筆加分紀錄記錄過得分或失分球員，系統 MUST 以清楚的提示取代「球員得失分統計」區塊，不得顯示全數為 0 的統計表。
- **FR-009**: 一位球員即使得分次數與造成失分次數皆為 0，只要他是這場比賽的參賽者之一，且比賽中至少有其他球員被記錄過得分/失分，系統 MUST 仍將該球員列在統計中並明確標示為 0。
- **FR-010**: 本功能新增的球員資訊、落點資訊、得失分統計 MUST 同時套用於目前所有可查看比賽詳情的既有對戰紀錄入口（某團對戰紀錄、會員個人跨團對戰紀錄、某團歷史戰績）。
- **FR-011**: 落點資訊與球員/統計資訊的顯示對象與可見範圍 MUST 與目前對戰紀錄既有的檢視權限（會員/訪客）完全一致，不得放寬或限縮。

### Key Entities

- **加分紀錄（既有）**：比賽中每一次 +1 得分事件，本功能不新增欄位，只新增「讀取並顯示」其關聯的落點紀錄。
- **落點紀錄（既有，計分當下已寫入）**：記錄某一次加分的得分球員、失分球員、羽球落點座標；目前僅在計分當下寫入，從未在任何「查看」畫面呈現過——本功能是第一個讀取並顯示它的畫面。
- **球員得失分統計（本功能新增的呈現概念，非新資料表）**：以「單場比賽」為範圍，加總每位參賽球員在該場所有落點紀錄中被記為得分球員與被記為失分球員的次數，即時計算後顯示，不落地儲存。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 對於已記錄得分/失分球員的加分紀錄，使用者查看比賽詳情時 100% 能在該筆紀錄旁直接看到球員暱稱，不需要任何額外點擊。
- **SC-002**: 使用者點擊任一筆已記錄落點的加分紀錄後，能在同一畫面（不重新整理、不跳轉頁面）立即看到該分的落點資訊。
- **SC-003**: 對於有任何一筆得失分球員紀錄的比賽，100% 的參賽球員都會出現在「球員得失分統計」中並顯示正確數字（含數字為 0 的球員）；沒有任何紀錄的比賽則 100% 顯示明確提示而非全零假數據。
- **SC-004**: 沒有開啟詳細計分模式、或所有加分都被跳過的既有比賽，其逐點加減分紀錄清單（每一列本身）在功能上線後與上線前 100% 視覺與行為一致，不出現任何球員標示或可點擊的落點展開；「球員得失分統計」區塊則依 FR-008 顯示明確的無資料提示，不受本條約束（該提示本身就是這類比賽在功能上線後的正確、預期行為，非誤導性的空白區塊）。

## Assumptions

- 「球員得失分統計」為即時計算的衍生資料，直接加總既有的落點紀錄，不需要新增資料表或背景批次任務。
- 落點資訊的呈現重用既有「詳細計分」計分畫面已經建立的球場示意圖呈現方式，維持視覺一致，而非另外設計一套新的圖表元件。
- 「得分次數」與「造成失分次數」為球員得失分統計唯一需要的兩個指標；本功能不涉及更細緻的失誤分類（例如發球失誤、界外等）統計，也不涉及排行榜、MVP 等衍生榮譽呈現。
- 點擊加分紀錄查看落點資訊，屬於既有比賽詳情對話框內的原地展開互動（詳見 Clarifications），不需要另外開啟新頁面、新路由，也不疊加新的對話框。
- 本功能只影響「查看對戰紀錄」的既有畫面，不新增、也不修改計分當下（詳細計分模式挑選畫面）的任何寫入邏輯或資料格式。
