# Feature Specification: 管理頁分數控制板支援比賽詳細設定

**Feature Branch**: `feature/admin-detailed-scoring`

**Created**: 2026-09-20

**Status**: Draft

**Input**: User description: "開團管理頁面的分數控制板，也要項控制頁面一樣，如果有開啟比賽詳細設定，加分的時候可以進行詳細設定。"

## 背景

「比賽詳細設定」是團的一個開關：打開之後，每記一分都可以順手記下這一分是怎麼來的——球落在場上哪個位置、誰得分、誰失分、以及這一分的結束方式（殺球、發球失誤、出界……）。這些資料是比賽紀錄頁、球員儀表板、關鍵分與對戰分析等統計的來源。

目前只有**公開計分連結**那一側支援這件事：控制頁面（單一場地控制板）、全場地控制板、記分板三處在開啟詳細設定時，按下「+」會先把分數加上去，同時跳出詳細記錄視窗讓計分者補齊資料。

但現場最常實際在計分的人——開團的管理員——用的是**開團管理頁面**裡的分數控制板。那裡的「+1」至今仍是純粹加一分，不會跳出任何詳細記錄視窗。結果是：

1. **同一場比賽的資料會有洞。** 管理員自己記的分沒有詳細資料，公開連結記的分有；同一場比賽的統計因此時準時不準，落點圖、得分球員排行都會漏掉一部分。
2. **開關等於沒作用。** 管理員在管理頁上打開「比賽詳細設定」，回到同一頁的分數控制板卻什麼都沒變——設定的地方和失效的地方是同一頁，特別容易被當成壞掉。
3. **想記詳細資料就得換頁面。** 管理員必須另外開一個公開控制連結才能記詳細資料，等於放棄管理頁上場地排程、換輪、名單全部看得到的便利。

本功能把管理頁分數控制板的計分體驗，補齊到與控制頁面一致：詳細設定開啟時，加分就能進行詳細設定；關閉時，維持現在的一鍵加分不變。

## Clarifications

### Session 2026-09-20

- Q: 「像控制頁面一樣」要到什麼程度？只有跳出詳細視窗，還是視窗裡的每個動作都要有？ → A: 完整對齊。詳細視窗裡的三個動作——**確認**（記下詳細資料）、**略過**（分數留著、不記詳細）、**取消這一分**（連同分數一起收回）——在管理頁都要能用，行為與控制頁面相同。管理員不該因為換了一個頁面就少一種修正手段。
- Q: 哪些頁面算在範圍內？ → A: 只有開團管理頁面裡的分數控制板。控制頁面、全場地控制板、記分板已經有了；成員檢視頁沒有計分功能，不在範圍。
- Q: 「-1」要不要也跳詳細視窗？ → A: 不要，與控制頁面一致。「-1」是修正手段，不是一個新的得分事件，沒有詳細資料可記。
- Q: 詳細設定是看團當下的設定，還是看這場比賽的設定？ → A: 看**這場比賽**的設定。每場比賽在建立時會記下當時團的設定值，之後團的開關再改也不影響已經開打的比賽——這個規則已經存在，管理頁只是跟著照做，不另外定義。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理員在管理頁加分後記錄這一分的詳細資料 (Priority: P1)

我是開團的管理員，人在場邊用開團管理頁面盯著全部場地。團裡已經開啟「比賽詳細設定」。某一場結束一個回合，我在該場地的分數控制板按下「+1」——比分立刻加上去，同時跳出詳細記錄視窗，讓我點球落在哪、誰得分、誰失分、這一分怎麼結束的。我確認後視窗關閉，這一分的詳細資料就跟從公開控制連結記的分一模一樣，進了比賽紀錄與統計。

**Why this priority**：這是整個功能的核心價值，也是使用者描述裡唯一明講的需求。只做這一則，管理員就不必再為了記詳細資料而另開公開連結，統計資料的缺口也補起來了。

**Independent Test**：開一個已啟用「比賽詳細設定」的團，排一場比賽，全程只從開團管理頁面的分數控制板計分，打完後到比賽紀錄頁檢查——每一分都應有落點與球員資料，與從控制頁面計分的對照組無法區分。

**Acceptance Scenarios**:

1. **Given** 一場詳細設定為開啟的進行中比賽顯示在開團管理頁面的分數控制板上, **When** 管理員按下任一邊的「+1」, **Then** 該邊比分 MUST 立即加一（不等詳細視窗處理完），且詳細記錄視窗 MUST 在同一次按壓中開啟。
2. **Given** 詳細記錄視窗已開啟且管理員已選好落點與球員, **When** 他按下確認, **Then** 這一分的詳細資料 MUST 被記錄並與該分綁定，視窗 MUST 關閉，分數控制板 MUST 回到可繼續計分的狀態。
3. **Given** 一場詳細設定為**關閉**的進行中比賽, **When** 管理員按下「+1」, **Then** 比分 MUST 加一且 MUST NOT 跳出任何詳細記錄視窗——行為與本功能實作前完全相同。
4. **Given** 詳細設定為開啟的比賽, **When** 管理員按下「-1」, **Then** 比分 MUST 減一且 MUST NOT 跳出詳細記錄視窗。
5. **Given** 管理員在管理頁記下了一分的詳細資料, **When** 任何人檢視該場比賽的紀錄與統計, **Then** 這一分 MUST 與從控制頁面記錄的分受到完全相同的對待，MUST NOT 因來源頁面不同而有任何差異。

### User Story 2 - 記錯了可以當場略過或收回這一分 (Priority: P2)

我在管理頁按了「+1」，詳細視窗跳出來。有時候我來不及看清楚球落在哪，就按「略過」——分數留著，詳細資料這一分不記。有時候是我按錯邊了，那就按「取消這一分」——連同剛剛加上去的那一分一起收回，比分回到按下之前。

**Why this priority**：現場計分節奏很快，按錯與看不清楚都很常見。沒有這兩個出口，詳細視窗會從幫手變成路障——管理員會被迫為了不擋比賽而亂填，反而污染統計資料。與 US1 分開是因為 US1 交付後功能已可用，這一則補的是修正路徑。

**Independent Test**：在管理頁對一場詳細設定開啟的比賽按「+1」，分別以「略過」與「取消這一分」結束視窗，驗證前者比分保留且無詳細資料、後者比分回到按下前。

**Acceptance Scenarios**:

1. **Given** 詳細記錄視窗因管理員按「+1」而開啟, **When** 他按下「略過」, **Then** 視窗 MUST 關閉，已加上的那一分 MUST 保留，且該分 MUST NOT 留下任何詳細資料。
2. **Given** 詳細記錄視窗因管理員按錯邊的「+1」而開啟, **When** 他按下「取消這一分」, **Then** 剛剛加上的那一分 MUST 被收回，雙方比分 MUST 回到按下「+1」之前的數字，視窗 MUST 關閉。
3. **Given** 剛剛那一分**讓比賽達到結束條件**（比賽已判定結束）, **When** 管理員在視窗中按下「取消這一分」, **Then** 系統 MUST 同時取消比賽的結束判定與那一分，該場比賽 MUST 回到進行中且比分正確。
4. **Given** 該場比賽已無法收回那一分（例如該輪已換輪、或同場地的下一場已經開始計分）, **When** 管理員按下「取消這一分」, **Then** 系統 MUST 在控制板上顯示可讀的失敗原因，MUST NOT 讓比分或比賽狀態進入錯誤或不一致的狀態。

---

### User Story 3 - 詳細視窗開著的時候不會被即時更新抽掉 (Priority: P3)

我按下的是賽末點——這一分一記完比賽就結束了。管理頁本來會因為「比賽結束」的即時通知立刻重畫整個場地區塊（改顯示下一場或等待中）。但我人還在詳細視窗裡填資料，視窗不該在我手指底下消失。我應該能安安穩穩把最後一分記完、或略過、或取消，視窗關上之後畫面才跟著更新到最新狀態。

**Why this priority**：只影響「這一分結束了比賽」與「其他人同時在操作」這兩種情境，不像 US1/US2 那樣每一分都遇得到；但賽末點往往正是最值得記錄的一分，漏掉的代價不小。

**Independent Test**：把一場比賽打到賽末點前一分，從管理頁按下決勝那一分，在詳細視窗開啟期間讓比賽結束通知抵達，驗證視窗仍然在、仍可完成記錄，且關閉後畫面顯示正確的賽後狀態。

**Acceptance Scenarios**:

1. **Given** 詳細記錄視窗開啟中, **When** 該分讓比賽結束、或其他裝置的計分／換輪造成畫面需要更新, **Then** 詳細記錄視窗 MUST 保持開啟且內容不變，管理員 MUST 能完成確認／略過／取消這一分。
2. **Given** 詳細記錄視窗開啟中且視窗背後的比分因這一分而改變, **When** 管理員看向控制板, **Then** 背景顯示的比分 MUST 已反映這一分（不是舊的數字）。
3. **Given** 管理員以任一方式（確認／略過／取消這一分）關閉了詳細記錄視窗, **When** 視窗關閉, **Then** 該場地區塊 MUST 更新到最新的真實狀態（下一場、等待中或已結束），MUST NOT 停留在視窗開啟期間的凍結畫面。
4. **Given** 管理員快速連按兩次同一個「+1」, **When** 第一次的計分請求尚未回應, **Then** 系統 MUST 只記一分，MUST NOT 產生兩個得分事件或兩個詳細記錄視窗。

---

### Edge Cases

- **加分成功、詳細資料沒記成**（網路中斷、伺服器拒絕）：那一分 MUST 保留，MUST NOT 因為詳細記錄失敗而被回滾；管理員 MUST 得到可讀的提示，比賽 MUST 能繼續計分。
- **這一分根本沒加成功**（伺服器拒絕，例如比賽已結束）：詳細記錄視窗 MUST 自行關閉，MUST NOT 停在視窗裡要求管理員替一個不存在的分填資料。
- **離線／連線中斷時**：分數控制板的所有操作（含「+1」與詳細視窗內的動作）MUST 依照現有的離線規則停用，與控制頁面一致。
- **這一分的詳細資料已經被記過**（另一台裝置搶先記了同一分）：系統 MUST 以可讀訊息告知，MUST NOT 覆蓋已記錄的資料，也 MUST NOT 讓管理員誤以為自己記成功了。
- **比賽建立時詳細設定是關閉的，之後團的開關才被打開**：這場比賽 MUST 維持一鍵加分，MUST NOT 跳出詳細視窗（沿用既有的「比賽沿用建立當下設定」規則）。反之亦然。
- **同一個管理頁上有多個場地同時在打**：任一場地的詳細視窗 MUST 只影響它自己那一場，MUST NOT 凍結或干擾其他場地的即時更新與計分。
- **視窗開啟期間管理員離開頁面或重新整理**：已加上的那一分 MUST 保留，未填完的詳細資料視為未記錄，比賽狀態 MUST 保持一致。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 開團管理頁面的分數控制板 MUST 依據該場比賽的詳細設定狀態決定「+1」的行為：開啟時進入詳細記錄流程，關閉時維持單純加一分。
- **FR-002**: 詳細設定開啟時，按下「+1」MUST 立即把該分計入比分，且 MUST NOT 讓比分的生效與否取決於管理員是否完成詳細記錄——比賽節奏不得被記錄動作拖慢。
- **FR-003**: 詳細設定開啟時，按下「+1」MUST 在同一次按壓中開啟詳細記錄視窗，不需要管理員再多按一次。
- **FR-004**: 詳細記錄視窗 MUST 提供與控制頁面相同的記錄項目（球的落點、得分球員、失分球員、這一分的結束方式），且 MUST 套用與控制頁面相同的填寫輔助與合理性檢查。
- **FR-005**: 詳細記錄視窗 MUST 提供「確認」「略過」「取消這一分」三個出口，行為與控制頁面相同。
- **FR-006**: 「略過」MUST 保留該分並關閉視窗，且 MUST NOT 為該分留下任何詳細資料。
- **FR-007**: 「取消這一分」MUST 收回剛加上的那一分，使比分回到按下「+1」之前的狀態。
- **FR-008**: 當被取消的那一分已使比賽達成結束條件時，「取消這一分」MUST 一併撤銷比賽的結束判定，使該場比賽回到進行中。
- **FR-009**: 當「取消這一分」因為賽程已往前推進（換輪、同場地下一場已開始計分等）而無法執行時，系統 MUST 於分數控制板上顯示可讀的失敗原因，且 MUST NOT 造成比分或比賽狀態不一致。
- **FR-010**: 「-1」按鈕 MUST 維持純粹減一分，MUST NOT 開啟詳細記錄視窗。
- **FR-011**: 詳細記錄視窗開啟期間，該場地區塊的顯示 MUST NOT 因為任何即時更新（比賽結束、換輪、他人計分）而被替換或移除；視窗以任一方式關閉後，該場地區塊 MUST 更新到最新的真實狀態。
- **FR-012**: 詳細記錄視窗開啟期間，視窗背後顯示的比分 MUST 已包含剛記下的這一分。
- **FR-013**: 系統 MUST 防止重複計分：在一次「+1」的請求完成前，重複按壓 MUST NOT 產生第二個得分事件或第二個詳細記錄視窗。
- **FR-014**: 從管理頁記錄的詳細資料 MUST 與從控制頁面記錄的完全等價——後續的比賽紀錄、落點呈現與各項統計 MUST NOT 因來源頁面不同而有任何差異。
- **FR-015**: 系統 MUST 讓分數控制板能夠判斷當前這場比賽是否啟用詳細設定，依據為該場比賽建立當下的設定快照，而非團當下的開關值。
- **FR-016**: 詳細資料記錄失敗時，已計入的該分 MUST 保留，系統 MUST 顯示可讀訊息，且比賽 MUST 能繼續正常計分。
- **FR-017**: 若「+1」本身未被系統接受，詳細記錄視窗 MUST 自動關閉，MUST NOT 要求管理員為一個不存在的得分填寫資料。
- **FR-018**: 分數控制板在離線／連線中斷期間 MUST 依現有規則停用所有計分與詳細記錄操作，規則與控制頁面一致。
- **FR-019**: 詳細記錄流程 MUST 沿用管理員既有的身分驗證路徑，MUST NOT 要求管理員額外開啟或持有公開計分連結。
- **FR-020**: 所有新增的畫面文字 MUST 沿用既有的多語系文案鍵，MUST NOT 引入僅單一語言可用的硬寫字串。

### Key Entities

- **比賽詳細設定（開關）**：團層級的設定，決定新建立的比賽是否啟用詳細記錄；每場比賽在建立時保存一份當下的設定快照，該場比賽之後一律依快照行事。
- **得分事件**：一次「+1」在比賽中產生的一筆得分紀錄，是詳細資料的掛載對象；一個得分事件最多對應一筆詳細資料。
- **落點詳細資料**：附在某個得分事件上的補充資訊——球的落點位置、得分球員、失分球員、這一分的結束方式；各欄位皆可為未填。
- **場地控制板（管理頁）**：開團管理頁面中每個場地一塊的計分區，顯示比分與發球站位，提供「+1」「-1」「提前結束」等操作。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在已啟用比賽詳細設定的團中，一場全程只從開團管理頁面計分的比賽，其可記錄詳細資料的分數比例，與一場全程從控制頁面計分的比賽相同（兩者皆為 100% 的得分皆有機會記錄）。
- **SC-002**: 按下「+1」後比分在畫面上更新所需的時間，與未啟用詳細設定時相同——管理員 MUST NOT 感覺到因為詳細視窗而變慢。
- **SC-003**: 詳細記錄視窗一旦開啟，在管理員主動以確認／略過／取消結束之前，100% 不會自行消失，包含該分為賽末點的情形。
- **SC-004**: 詳細設定關閉時，開團管理頁面分數控制板的操作流程與本功能實作前逐步相同，0 個新增的點擊或視窗。
- **SC-005**: 在管理頁按錯邊的情況下，管理員可在不離開該頁面、不使用其他修正工具的前提下 100% 收回該分，包含該分已使比賽結束的情形。
- **SC-006**: 同一場比賽中混合使用管理頁與控制頁面計分後，比賽紀錄與統計頁面呈現的詳細資料 MUST 無法分辨哪一分來自哪個頁面。
- **SC-007**: 管理員不再需要為了記錄詳細資料而另外開啟公開計分連結——完成一場含詳細資料的比賽所需切換的頁面數由 2 降為 1。

## Assumptions

- **既有的詳細計分規則原封不動沿用。** 可記錄哪些欄位、欄位之間的合理性檢查、失敗時的錯誤語意、一個得分只能記一次等規則，全部沿用控制頁面已在使用的同一套規則；本功能不重新定義、不放寬、也不新增規則。
- **後端已具備管理員身分的詳細記錄能力。** 管理員路徑的計分、詳細資料記錄與撤銷比賽結束等能力已經存在（與公開連結路徑同一套業務規則、不同驗證方式），本功能主要是把管理頁的計分體驗接上去，並補齊分數控制板判斷開關所需的資訊。
- **範圍限於開團管理頁面的分數控制板。** 控制頁面、全場地控制板、記分板已支援詳細記錄，不在本次改動範圍；成員檢視頁沒有計分功能，同樣不在範圍。
- **管理頁與控制頁面看到的是同一個詳細記錄介面。** 管理頁不另外設計一套記錄畫面——兩邊的視窗在外觀、操作與用語上完全相同，才能保證行為一致，也避免兩套介面日後各自演化。
- **「取消這一分」屬於本功能範圍。** 使用者要求「像控制頁面一樣」，而取消這一分是控制頁面詳細視窗的固有出口之一；少了它，管理員在管理頁按錯邊時反而比現在更難修正。
- **不改變任何既有的統計定義。** 本功能只是讓更多分數有機會帶上詳細資料，統計本身的計算方式不動。
