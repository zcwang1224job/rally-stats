# Feature Specification: 對戰紀錄衍生統計（發球得分率、比分走勢、每分耗時、落點分布）

**Feature Branch**: `feature/match-record-serve-stats`

**Created**: 2026-09-17

**Status**: Draft

**Input**: User description: "對戰紀錄衍生統計（不新增／不修改任何資料表，只讀取既有資料）：在既有的「對戰紀錄詳細頁」（單場已完成比賽）新增四類資訊。(1) 發球方得分率／接發球得分率，算出每一隊、以及每位球員的數字；這些發球紀錄從 030 起就已寫入，但目前沒有任何查看畫面在讀。(2) 比分走勢摘要：每隊最長連續得分、最大領先分差、逆轉次數與發生時的比分。(3) 每分耗時：平均每分耗時、最長的一分（及其當時比分），作為回合長度的粗估。(4) 落點分布圖：把既有落點紀錄彙整成每位球員的「得分落點」與「失分落點」球場分布圖（目前只有逐點明細）。需妥善處理：-1 修正事件、030 之前的舊比賽沒有發球紀錄、簡易計分模式比賽沒有落點資料、紀錄不完整的比賽——這些情況要顯示「無資料」提示而不是錯誤數字。沿用既有對戰紀錄詳細入口與既有授權邊界，不新增權限。中英文雙語介面。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 發球／接發球得分率 (Priority: P1)

我是會員或訪客，正在查看「對戰紀錄」中某場已完成比賽的詳情。我想知道這場比賽裡，每一隊（雙打時再細到每位球員）「輪到自己發球時拿下幾分」、「接對方發球時拿下幾分」，藉此判斷自己是發球局守不住、還是接發球搶不到分。

**Why this priority**：系統從 030 起，每一分都已經記下「誰在發球、四個人各站哪一區」，但這份資料至今沒有任何查看畫面在讀，等於白白記錄。這是四類資訊中唯一「資料已存在、卻完全沒有回饋給使用者」的一項，也是羽球檢討最常問的第一個問題，因此優先度最高。

**Independent Test**：任選一場 030 上線後完成的比賽，點進其對戰紀錄詳情，可獨立驗證：畫面出現雙方各自的「發球時得分／發球總分數」與「接發球時得分／接發球總分數」，且數字與逐點紀錄一筆一筆人工核對一致；雙打比賽另外列出四位球員各自的數字。

**Acceptance Scenarios**:

1. **Given** 一場 030 上線後完成的比賽, **When** 使用者查看比賽詳情, **Then** 系統 MUST 顯示雙方各自的「發球時得分數／發球總分數」與「接發球時得分數／接發球總分數」，並同時呈現次數與百分比。
2. **Given** 一場雙打比賽, **When** 使用者查看發球統計, **Then** 系統 MUST 另外列出四位參賽球員各自擔任發球者時的「得分數／發球總分數」，以及各自擔任接發球者時的「得分數／接發球總分數」。
3. **Given** 一場單打比賽, **When** 使用者查看發球統計, **Then** 系統 MUST 只顯示隊伍（即球員本人）層級的數字，MUST NOT 重複列出內容相同的球員層級區塊。
4. **Given** 任一場比賽的第一分, **When** 系統計算發球統計, **Then** 該分 MUST NOT 計入任何一方的發球或接發球分母（開賽時的發球方未被記錄，見 Assumptions），且畫面 MUST 以一行說明讓使用者知道「第一分不列入發球統計」，使分母加總與總比分的 1 分差距有合理解釋。
5. **Given** 某位球員整場比賽從未輪到發球（例如比賽很快結束）, **When** 使用者查看球員層級統計, **Then** 該球員 MUST 仍列在清單中，其發球數字顯示為「0／0」並以「—」取代百分比，MUST NOT 顯示 0% 或從清單中省略。
6. **Given** 一場 030 上線前完成、沒有任何發球紀錄的舊比賽, **When** 使用者查看比賽詳情, **Then** 系統 MUST 以清楚的提示（例如「此比賽沒有發球紀錄」）取代發球統計區塊，MUST NOT 顯示全數為 0 的表格。

### User Story 2 - 比分走勢摘要 (Priority: P2)

我是同一位使用者。既有的趨勢圖讓我「看到」比分曲線，但我想直接讀到幾個關鍵數字：每一隊最長連續拿下幾分、最大曾經領先幾分、領先方一共易手幾次、每次易手發生在幾比幾。

**Why this priority**：這些數字完全由既有的逐分紀錄推導，適用於**所有**有完整逐分紀錄的比賽（不限詳細計分模式、不限 030 之後），涵蓋面最廣；但它是把既有趨勢圖「摘要化」的加值，不像 US1 是把一份從未呈現的資料首度攤開，因此排在 US1 之後。

**Independent Test**：任選一場有完整逐分紀錄的比賽，可獨立驗證：畫面顯示的每隊最長連續得分、最大領先分差、領先易手次數與各次易手比分，與趨勢圖／逐點清單人工核對一致。

**Acceptance Scenarios**:

1. **Given** 一場有完整逐分紀錄的已完成比賽, **When** 使用者查看比賽詳情, **Then** 系統 MUST 顯示雙方各自的「最長連續得分」分數，以及該段連續得分開始與結束時的比分。
2. **Given** 同一場比賽, **When** 使用者查看走勢摘要, **Then** 系統 MUST 顯示雙方各自的「最大領先分差」及其發生時的比分；從未領先過的一方顯示為 0。
3. **Given** 比賽過程中領先方曾經易手（原本落後的一方變成領先）, **When** 使用者查看走勢摘要, **Then** 系統 MUST 顯示領先易手的總次數，並列出每一次易手當下的比分。
4. **Given** 一場比賽由同一方從頭領先到尾, **When** 使用者查看走勢摘要, **Then** 領先易手次數 MUST 顯示為 0，且 MUST NOT 顯示空白的易手清單區塊。
5. **Given** 比賽過程中出現平手後原領先方再度領先（平手但未被反超）, **When** 系統計算領先易手, **Then** 該情況 MUST NOT 計為一次易手——只有「領先的一方換人」才算。

### User Story 3 - 每分耗時 (Priority: P3)

我是同一位使用者，想大致知道這場比賽的節奏：平均一分打多久、最久的一分是幾比幾的時候、打了多久。

**Why this priority**：同樣由既有逐分紀錄的時間推導、不依賴任何新資料；但它只是「回合長度的粗估」（時間差包含撿球、走位與計分員按鍵的延遲），精確度與檢討價值都低於前兩項，因此排第三。

**Independent Test**：任選一場有完整逐分紀錄的比賽，可獨立驗證：畫面顯示平均每分耗時、最長一分的耗時與當時比分，數字與逐點清單上相鄰兩分的時間差核對一致，且畫面上明確標示此為估計值。

**Acceptance Scenarios**:

1. **Given** 一場有完整逐分紀錄的已完成比賽, **When** 使用者查看比賽詳情, **Then** 系統 MUST 顯示「平均每分耗時」與「最長的一分」（含耗時與該分結束後的比分）。
2. **Given** 同一場比賽, **When** 系統計算每分耗時, **Then** 第一分的耗時 MUST 以比賽開始時間起算，其餘各分以上一個有效得分的時間起算。
3. **Given** 兩個有效得分之間曾發生比分修正（-1）, **When** 系統計算每分耗時, **Then** 該段時間差 MUST NOT 計入平均值，也 MUST NOT 被選為「最長的一分」（那段時間包含了修正操作，不代表回合長度）。
4. **Given** 任一場顯示每分耗時的比賽, **When** 使用者查看該區塊, **Then** 畫面 MUST 以文字明確標示此為「估計值，包含回合之間的間隔」，避免使用者誤以為是精準的回合計時。

### User Story 4 - 球員落點分布圖 (Priority: P3)

我是同一位使用者，查看一場開啟過詳細計分模式的比賽。目前我只能一筆一筆點開每一分的落點；我想選定某一位球員，一次看到他這場比賽所有「得分」的落點分布，以及所有「失分」的落點分布，看出他習慣打哪裡得分、哪一區容易失分。

**Why this priority**：把 032 已經攤開的逐點落點「彙整成一張圖」，洞見價值高，但只適用於開啟詳細計分模式、且計分員確實標了落點的比賽，涵蓋面是四項中最窄的，因此與 US3 同列 P3。

**Independent Test**：任選一場有多筆落點紀錄的比賽，可獨立驗證：在比賽詳情選擇某位球員後，球場示意圖上同時標出該球員被記為得分球員的全部落點、以及被記為失分球員的全部落點，兩類標記可明確區分，且點數與位置與逐點明細逐筆核對一致。

**Acceptance Scenarios**:

1. **Given** 一場有落點紀錄的比賽, **When** 使用者在比賽詳情選擇某一位參賽球員, **Then** 系統 MUST 在球場示意圖上標出該球員所有「得分落點」（他被記為得分球員的那些分）與所有「失分落點」（他被記為失分球員的那些分）。
2. **Given** 同一張分布圖, **When** 使用者觀看得分與失分兩類標記, **Then** 兩類標記 MUST 以顏色**以外**的方式（例如不同形狀，並搭配圖例文字）加以區分，MUST NOT 僅依賴顏色。
3. **Given** 同一張分布圖, **When** 使用者只想看其中一類, **Then** 使用者 MUST 能分別切換顯示／隱藏「得分落點」與「失分落點」。
4. **Given** 某一分記錄了球員但當時沒有標示落點, **When** 系統繪製分布圖, **Then** 該分 MUST NOT 出現在圖上，但圖旁 MUST 顯示「已標落點的分數／該球員有紀錄的總分數」，讓使用者知道圖上的點不是全部。
5. **Given** 落點在界外（出界球）, **When** 系統繪製分布圖, **Then** 該落點 MUST 顯示在球場線外的對應位置，MUST NOT 被裁切或強制拉回界內。
6. **Given** 一場比賽完全沒有任何落點紀錄（簡易計分模式，或詳細計分但每一分都未標落點）, **When** 使用者查看比賽詳情, **Then** 系統 MUST 以清楚的提示（例如「此比賽沒有落點紀錄」）取代分布圖區塊，MUST NOT 顯示空白球場。
7. **Given** 某位球員在這場比賽沒有任何落點紀錄、但其他球員有, **When** 使用者選擇該球員, **Then** 系統 MUST 顯示該球員專屬的無資料提示，其他球員的分布圖不受影響。

---

### Edge Cases

- **被撤銷的得分**：比分修正（-1）代表撤銷該隊最近一筆尚未被撤銷的得分。四類統計 MUST 只計入「最終仍然成立」的得分——被撤銷的那一分、以及修正動作本身，都不計入得分數、連續得分、領先分差、發球／接發球分母或每分耗時。驗證基準：四類統計所依據的有效得分總數 MUST 等於最終比分兩隊相加。
- **紀錄不完整的比賽**（逐分紀錄為「部分」或「無」，016 既有判定）：四個區塊 MUST 一律顯示無資料提示，MUST NOT 以殘缺的紀錄算出看似合理、實則錯誤的數字。
- **比賽中途才開啟詳細計分模式**：開啟前的得分沒有落點，開啟後才有——分布圖只呈現有落點的分數，並透過「已標落點／總分數」的比例讓使用者理解涵蓋範圍（同 US4 情境 4）。
- **已捨棄（abandoned）的比賽**：依既有規則本就不會出現在任何對戰紀錄清單中，本功能不另外處理。
- **訪客（Guest）球員**：暱稱與統計的呈現方式比照 032 既有的球員得失分統計，不因身分不同而有差異。
- **多個入口**：目前所有可以開啟「比賽詳情」的既有入口（某團對戰紀錄、會員個人跨團對戰紀錄、某團歷史戰績、好友的對戰紀錄）共用同一個詳情畫面——本功能 MUST 同時套用到全部入口，不得只有其中之一支援。
- **畫面長度**：比賽詳情已有趨勢圖、逐點清單、球員得失分統計；新增四個區塊後，在手機螢幕上 MUST 仍可順暢瀏覽（例如分區收合或分頁），不得讓既有內容被擠到難以找到。

## Requirements *(mandatory)*

### Functional Requirements

**共通**

- **FR-001**: 系統 MUST 在既有的比賽詳情畫面（單場已完成比賽）新增四個資訊區塊：發球／接發球得分率、比分走勢摘要、每分耗時、球員落點分布圖。
- **FR-002**: 四個區塊的所有數字 MUST 只依據「最終仍然成立」的得分計算；比分修正（-1）視為撤銷該隊最近一筆尚未被撤銷的得分，被撤銷的得分與修正動作本身皆不計入。
- **FR-003**: 每個區塊在其所需資料不存在時，MUST 各自獨立顯示明確的無資料提示，MUST NOT 顯示全數為 0 的表格、空白圖表或錯誤數字；一個區塊無資料 MUST NOT 影響其他有資料的區塊正常顯示。
- **FR-004**: 逐分紀錄不完整（「部分」或「無」）的比賽，四個區塊 MUST 一律顯示無資料提示。
- **FR-005**: 本功能 MUST 同時套用於目前所有可查看比賽詳情的既有入口（某團對戰紀錄、會員個人跨團對戰紀錄、某團歷史戰績、好友的對戰紀錄）。
- **FR-006**: 新增資訊的顯示對象與可見範圍 MUST 與目前對戰紀錄既有的檢視權限完全一致，不得放寬或限縮，亦不新增任何權限。
- **FR-007**: 本功能新增的所有顯示文字（標題、欄位名稱、無資料提示、說明文字）MUST 同時提供繁體中文與英文，並隨使用者既有的語言設定切換。
- **FR-008**: 本功能 MUST NOT 改變計分當下的任何行為，也 MUST NOT 新增或修改任何已儲存的比賽資料；所有統計皆為查看當下由既有紀錄推導。
- **FR-009**: 新增四個區塊後，比賽詳情畫面在手機螢幕上 MUST 仍可順暢瀏覽，既有內容（趨勢圖、逐點清單、球員得失分統計）MUST 維持容易找到。

**發球／接發球得分率**

- **FR-010**: 系統 MUST 顯示雙方各自的「發球時得分數／發球總分數」與「接發球時得分數／接發球總分數」，同時呈現次數與百分比。
- **FR-011**: 某一分的「發球方／發球者／接發球者」MUST 以**該分開打之前**的發球狀態為準（即前一個有效得分結束後記錄下來的發球者與站位），MUST NOT 使用該分結束之後的發球狀態——後者恆等於得分方，會使發球得分率恆為 100% 而失去意義。
- **FR-012**: 每場比賽的第一分 MUST NOT 計入任何發球或接發球分母，且畫面 MUST 以一行說明告知使用者。
- **FR-013**: 雙打比賽 MUST 另外列出四位參賽球員各自擔任發球者、擔任接發球者（站在發球者斜對角的那位球員）時的得分數與總分數；單打比賽 MUST NOT 重複顯示球員層級區塊。
- **FR-014**: 分母為 0 的項目 MUST 顯示為「0／0」並以「—」取代百分比；所有參賽球員 MUST 都列出，不得省略。
- **FR-015**: 沒有任何發球紀錄的比賽 MUST 顯示無資料提示。

**比分走勢摘要**

- **FR-016**: 系統 MUST 顯示雙方各自的最長連續得分分數，以及該段連續得分開始與結束時的比分；若同一方有多段長度相同的最長連續得分，顯示最早發生的那一段。
- **FR-017**: 系統 MUST 顯示雙方各自的最大領先分差及其發生時的比分；從未領先的一方顯示為 0。
- **FR-018**: 系統 MUST 顯示領先易手的總次數，並列出每一次易手當下的比分；「易手」定義為領先的一方由一隊變為另一隊，中間經過平手不另外計次，平手後原領先方再度領先不算易手。易手次數為 0 時 MUST NOT 顯示空白清單。

**每分耗時**

- **FR-019**: 系統 MUST 顯示平均每分耗時，以及耗時最長的一分（含耗時與該分結束後的比分）。
- **FR-020**: 第一分的耗時 MUST 以比賽開始時間起算；其餘各分以上一個有效得分的時間起算。
- **FR-021**: 兩個有效得分之間若曾發生比分修正，該段時間差 MUST NOT 計入平均值，也 MUST NOT 被選為最長的一分。
- **FR-022**: 此區塊 MUST 以文字明確標示為估計值、且包含回合之間的間隔。

**球員落點分布圖**

- **FR-023**: 使用者 MUST 能選擇這場比賽任一位參賽球員，並在球場示意圖上同時看到該球員的全部得分落點與全部失分落點。
- **FR-024**: 得分落點與失分落點 MUST 以顏色以外的方式（形狀並搭配圖例文字）區分，且使用者 MUST 能分別切換兩者的顯示。
- **FR-025**: 界外落點 MUST 顯示在球場線外的對應位置，不得裁切或拉回界內。
- **FR-026**: 圖旁 MUST 顯示該球員「已標落點的分數／有紀錄的總分數」（得分與失分各自一組）。
- **FR-027**: 整場比賽沒有任何落點紀錄時 MUST 顯示無資料提示取代整個區塊；個別球員沒有落點時顯示該球員專屬的無資料提示。
- **FR-028**: 分布圖的球場方向與座標呈現 MUST 與既有逐點落點展開圖（032）一致，使同一個落點在兩處看起來位於球場的同一位置。

### Key Entities

- **加分／修正紀錄（既有）**：比賽中每一次 +1 得分與 -1 修正，含當下比分與時間。本功能不新增欄位，只新增由它推導的走勢摘要與每分耗時。
- **發球紀錄（既有，030 起於計分當下寫入）**：每一次得分**結束後**的發球狀態快照——下一分由哪一隊、哪一位球員發球，以及四位球員各自站在左／右哪一區。至今沒有任何查看畫面讀取它；本功能是第一個。注意它記錄的是「得分之後」的狀態，因此某一分的發球者要從**前一筆**紀錄取得。
- **落點紀錄（既有，031/032 起於詳細計分模式下寫入）**：某一次得分的得分球員、失分球員與羽球落點座標（三者皆可能未填）。032 已在逐點明細中呈現；本功能新增以球員為單位的彙整分布。
- **衍生統計（本功能新增的呈現概念，非新資料）**：以「單場比賽」為範圍，於查看當下由上述既有紀錄推導，不落地儲存。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 對於 030 上線後完成、逐分紀錄完整的比賽，使用者開啟比賽詳情後不需任何額外點擊或計算，即可讀到雙方的發球得分率與接發球得分率；抽樣 10 場人工逐分核對，數字 100% 一致。
- **SC-002**: 對於逐分紀錄完整的比賽，走勢摘要（最長連續得分、最大領先、領先易手次數與比分）與人工核對趨勢圖的結果 100% 一致，包含含有比分修正的比賽。
- **SC-003**: 四類統計所依據的有效得分總數，在 100% 的比賽中等於最終比分兩隊相加（發球統計另扣除第一分）。
- **SC-004**: 缺少對應資料的比賽（舊比賽無發球紀錄、簡易模式無落點、逐分紀錄不完整），100% 顯示明確的無資料提示，0 場出現全零表格、空白圖表或 100%／0% 之類的誤導性數字。
- **SC-005**: 使用者選定球員後，能在同一畫面（不重新整理、不跳轉頁面）立即看到該球員的得分／失分落點分布，圖上點數與逐點明細中該球員有落點的紀錄數 100% 一致。
- **SC-006**: 開啟一場 40 分以上的比賽詳情，新增區塊不讓使用者感受到比功能上線前明顯更慢（畫面仍在 2 秒內可讀）。
- **SC-007**: 切換中／英文後，新增的四個區塊 100% 的文字皆隨之切換，無殘留未翻譯字串。
- **SC-008**: 在手機螢幕寬度下，使用者能在 3 次以內的捲動或點擊找到既有的逐點清單與四個新增區塊中的任何一個。

## Assumptions

- **發球紀錄是「得分之後」的快照**：030 在每次得分後先完成換發球判定、再寫入快照，因此每筆紀錄上的發球隊伍恆等於該分得分方。某一分「開打時誰在發球」必須取自前一個有效得分的快照；這是既有資料的實際語意，本功能依此推導，不修改 030 的寫入方式。
- **第一分的發球方無法得知**：開賽時系統隨機決定的初始發球方與發球者，沒有被另外保存（只存在於比賽進行中的即時狀態，隨後即被覆寫）。因此每場比賽的第一分一律不列入發球統計。若日後希望補上，需要另開功能在開賽當下保存初始發球狀態——這會新增儲存欄位，明確不在本功能範圍內。
- **修正（-1）的撤銷對象**：視為撤銷該隊「最近一筆尚未被撤銷」的得分，與既有計分邏輯在修正時收回該隊最後一筆落點紀錄的做法一致。
- **每分耗時是粗估**：時間差來自計分員按下加分的時刻，包含回合之間撿球、走位與按鍵延遲，只能反映比賽節奏，不是精準的回合計時；本功能不新增任何計時操作。
- **所有統計為查看當下即時推導**：不需要新增儲存、背景批次任務或回填舊資料；舊比賽有什麼資料就呈現什麼，沒有就顯示無資料提示。
- **範圍僅限單場比賽**：跨場次彙整（個人長期趨勢、搭檔組合表現、對特定對手的勝率）不在本功能範圍，留待後續功能。
- **不涉及新的記錄項目**：得分結束方式（主動得分／受迫性失誤／非受迫性失誤）、球種等需要計分員多記一項的資訊，不在本功能範圍。
- **落點分布以「點狀分布」呈現**：單場比賽一位球員通常只有十幾到二十幾個落點，數量不足以形成有意義的密度熱區，因此以逐點標記的分布圖呈現，而非色塊式熱力圖；球場示意圖重用既有的呈現方式以維持視覺一致。
- **多語系沿用既有架構**：中英文切換沿用 024 已建立的語言設定與語系檔機制，本功能只新增文字項目。
