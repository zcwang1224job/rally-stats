# Feature Specification: 運動簡約風視覺改版與行動裝置操作優化

**Feature Branch**: `[008-sport-minimalist-ui]`

**Created**: 2026-09-01

**Status**: Draft

**Input**: User description: "將web 畫面設計運動簡約風，且使用者體驗要在平板手機上都方便操作"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 即時計分板與控制板的行動裝置操作 (Priority: P1)

現場計分員與旁觀者透過手機或平板開啟計分板、單一場地控制板、全部場地控制板連結時，畫面套用運動簡約風格（大膽字體、高對比配色、圖示化狀態），所有可點擊的按鈕（+1/-1、提前結束等）在手機直向與平板橫向下皆有足夠大小與間距，方便在球場邊快速、準確點擊。

**Why this priority**: 這是全系統操作頻率最高、且直接在球場邊以手機/平板進行的畫面；一旦按鈕太小或版面跑版，可能導致誤觸-1、誤判比分等直接影響比賽正確性的問題，優先度最高。

**Independent Test**: 可獨立用手機瀏覽器開啟一個既有場地的控制板連結與計分板連結，實測按鈕可點擊區域大小、比分文字在手機直向下的可視距離、以及平板橫向下的版面是否正常，無需依賴其他頁面改版。

**Acceptance Scenarios**:

1. **Given** 計分員以手機直向開啟控制板連結，**When** 檢視 +1/-1 與提前結束按鈕，**Then** 每個按鈕的可點擊區域達到最小可觸控尺寸標準，且彼此間距足以避免誤觸相鄰按鈕。
2. **Given** 旁觀者以平板橫向開啟計分板連結，**When** 畫面載入，**Then** 比分、Round 編號、雙方名稱皆維持原有「可遠距離閱讀」的清晰度，版面不因平板寬度而跑版或留下大量未使用的空白。
3. **Given** 控制板或計分板顯示連線中斷或「等待下一場」等狀態，**When** 使用者檢視畫面，**Then** 狀態說明同時有文字與圖示呈現，不僅依賴顏色區分（延續既有無障礙原則）。

---

### User Story 2 - 加入團與團內成員視圖的行動裝置操作 (Priority: P2)

一般使用者（含 Guest）以手機掃描 QR Code 或點擊連結加入團、查看賽程/戰績/對戰紀錄、退出組團時，表單欄位、按鈕、確認彈窗在手機小螢幕上皆清楚易讀、方便點擊，不需要橫向捲動或雙指縮放畫面即可完成操作。

**Why this priority**: 加入與查看是使用者接觸系統最頻繁的入口流程，且多半透過手機完成（例如掃描 QR Code 情境）；重要性僅次於直接影響比賽正確性的計分板/控制板。

**Independent Test**: 可獨立用手機開啟一個團的加入連結，走完密碼驗證（若有）、暱稱輸入、確認加入的完整流程，並開啟一般成員視圖的賽程、戰績、對戰紀錄、退出組團四個分頁，驗證表單與按鈕在手機尺寸下皆可正常操作，無需依賴管理頁或會員頁的改版。

**Acceptance Scenarios**:

1. **Given** 使用者以手機開啟加入連結，**When** 依序完成密碼驗證與暱稱輸入，**Then** 每個步驟的輸入框與送出按鈕皆清楚可見、易於點擊，且不需要橫向捲動頁面。
2. **Given** 一般成員以手機檢視戰績頁的四狀態表格，**When** 表格欄位數量隨輪次增加，**Then** 表格在手機寬度下提供可用的檢視方式（例如允許表格區域本身橫向捲動），且不影響頁面其餘部分的版面。
3. **Given** 一般成員點擊「退出組團」，**When** 二次確認彈窗顯示於手機畫面，**Then** 彈窗內容完整可讀、確認與取消按鈕皆清楚可點擊，不超出螢幕範圍。

---

### User Story 3 - 開團管理與會員頁面的行動裝置操作 (Priority: P3)

團管理員與已登入會員以手機或平板進行開團、編輯團設定、場地管理、賽程輪替操作、踢除成員，以及會員登入、好友管理、個人設定、跨團對戰紀錄查詢時，所有既有管理與會員功能在手機直向與平板下皆可正常操作，不因螢幕縮小而出現按鈕重疊、選單無法展開、或功能入口消失的狀況。

**Why this priority**: 管理與會員相關操作的頻率通常低於加入/查看與即時計分，且部分情境使用者更可能使用桌機或平板；但仍需確保行動裝置上功能完整可用，優先度列為第三。

**Independent Test**: 可獨立用手機或平板開啟一個團的管理頁，測試建立場地、編輯團設定、踢除成員、Next Round 等管理操作，以及登入會員帳號後檢視好友列表、個人設定、跨團對戰紀錄，確認每個操作在小螢幕下皆可正常完成，無需依賴計分板或加入流程的改版。

**Acceptance Scenarios**:

1. **Given** 管理員以手機直向開啟管理頁，**When** 檢視團設定、場地管理、賽程控制等區塊，**Then** 各區塊之操作按鈕與輸入欄位皆可正常點擊與輸入，功能區塊之間有清楚的視覺區隔，不會互相重疊。
2. **Given** 管理員觸發任一具破壞性的操作（解散團、踢除成員等），**When** 二次確認彈窗顯示，**Then** 彈窗在手機與平板下皆完整顯示，不因螢幕尺寸而截斷文字或按鈕。
3. **Given** 已登入會員以手機檢視跨團對戰紀錄與彙總統計，**When** 頁面載入，**Then** 彙總數字與列表項目皆清楚可讀，分頁按鈕可正常點擊切換頁次。

---

### Edge Cases

- 在螢幕寬度更小的裝置（例如寬度 320px 上下的舊型手機）上，畫面是否仍維持可操作而不破版？
- 使用者在平板進行多工分割畫面（例如僅分配畫面一半寬度）瀏覽時，可用寬度可能遠小於平板全螢幕寬度，版面是否仍正常運作？
- 使用者操作計分板/控制板途中將手機從直向轉為橫向（或反之），畫面是否能正常重新排版而不遺失目前狀態？
- 既有頁面中已定案的無障礙設計（例如狀態呈現不可僅靠顏色區分、二次確認彈窗）在視覺改版後是否完整保留，未因改版而遺漏？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 對目前所有已實作的既有 web 畫面（開團與管理、場地管理、賽程與輪替、加入團、團內成員視圖、會員與好友、即時計分板與控制板）套用統一的「運動簡約風」視覺語言，MUST NOT 讓部分頁面沿用改版前的視覺風格而造成整體不一致。
- **FR-002**: 每一個可互動元件（按鈕、連結、輸入框、下拉選單、確認彈窗中的按鈕、導覽項目）在觸控裝置上 MUST 具備足夠的可點擊區域與間距，避免相鄰元件被誤觸。
- **FR-003**: 所有頁面 MUST 支援響應式版面配置，在手機直向、手機橫向、平板直向、平板橫向等常見尺寸下皆 MUST NOT 出現版面破版、文字溢出、或需要橫向捲動整個頁面才能看到核心內容的狀況（表格/清單本身允許區域性橫向捲動不在此限）。
- **FR-004**: 即時計分板與控制板頁面之比分數字 MUST 延續既有「可遠距離閱讀」需求，在手機直向模式下同樣 MUST 清楚可辨識，MUST NOT 因視覺改版而縮小至難以辨識的程度。
- **FR-005**: 任何用於傳達狀態的視覺元素（例如戰績表格的四狀態標示、連線中斷提示、場地等待狀態、需密碼/公開標示）MUST 延續既有「不可僅靠顏色作為唯一區分依據」原則，新視覺風格下仍 MUST 搭配圖示或文字標籤。
- **FR-006**: 所有既有的二次確認彈窗（解散團、刪除場地、踢除成員、退出組團、提前結束比賽等）MUST 在視覺改版後保留原有的確認流程與資訊揭露內容，MUST NOT 因改版而移除或弱化確認步驟。
- **FR-007**: 具有多個分頁或選單項目的頁面（管理頁、一般成員視圖）MUST 在手機尺寸下提供清楚可觸控的導覽方式，MUST NOT 要求使用者以雙指縮放才能看清或點擊導覽項目。
- **FR-008**: 本次改版 MUST NOT 變更任何既有頁面之底層業務邏輯、API 合約、或既有規格（001–007）已定義之功能行為——範圍僅限視覺呈現與版面配置調整。
- **FR-009**: 系統 MUST 保留桌面／筆電瀏覽情境下既有頁面的可用性，即改版後桌面版面 MUST NOT 因行動裝置優化而變得無法正常操作，即使桌面體驗非本次驗收重點。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在標準手機（約 375×667）與平板（約 768×1024）兩種視窗尺寸下，全部既有頁面之核心操作（開團、加入團、查看賽程/戰績/對戰紀錄、計分、控制板操作、會員登入、好友管理）皆可在不需要縮放畫面、且不需要橫向捲動整個頁面的情況下完成。
- **SC-002**: 計分板與控制板頁面上的 +1/-1 與其他操作按鈕，其可點擊區域 100% 達到業界建議的最小可觸控尺寸（見 Assumptions）。
- **SC-003**: 找 5 位以上未曾使用過本系統的受測者，以手機完成「開啟加入連結 → 加入團 → 查看賽程 → 查看戰績 → 退出組團」全流程，90% 以上可在無人協助的情況下獨立完成。
- **SC-004**: 視覺走查（design QA）確認改版後每一頁面的既有功能入口（按鈕、連結、選單項目）數量與可達性與改版前一致，不因版面調整而遺漏任何既有功能。

## Assumptions

- 「運動簡約風」定義為：大膽且高對比的字體與配色、扁平化卡片與按鈕、圖示搭配文字的狀態呈現、避免繁複陰影與裝飾性元素；具體色票、字型、元件庫等技術性選型留待 `/speckit-plan` 決定，不在本規格定義範圍內。
- 本次改版範圍涵蓋目前已實作的全部 7 份既有規格（001-create-manage-group ~ 007-live-scoreboard）所對應的全部畫面，而非單一頁面的局部調整。
- 觸控可點擊區域之最小尺寸採用業界慣例（例如 WCAG 2.5.5 建議之 44×44 CSS px 或同等標準），作為驗收基準，非本規格另行定義新標準。
- 桌面／筆電瀏覽並非本次優化的主要目標對象，但既有桌面體驗 MUST NOT 因本次改版而劣化。
- 本次規格僅涉及視覺呈現與版面配置調整，不涉及任何新增功能、資料模型、API 合約變更；憲章原則 VIII（i18n 架構）與既有錯誤代碼、顯示文字的對應規則不受本次改版影響。
- 「平板」與「手機」之尺寸範圍採業界常見定義（手機約 360–430px 寬、平板約 768–1024px 寬），實際中斷點（breakpoint）數值留待 `/speckit-plan` 決定。
