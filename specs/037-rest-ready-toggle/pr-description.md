# 037 休息／準備切換

`feature/rest-toggle` → `ut`

## 這個 PR 做了什麼

在「在團裡」與「離開」之間加入第三種狀態「休息中」：人還在團裡、紀錄與排名都不受影響，只是暫時不被排上場；按「準備好了」就回到排程，而且**不會因為休息而得到插隊的優先權**。

| 使用者故事 | 內容 |
|---|---|
| US1 自己切換 | 成員頁名單上方一顆「我要休息／準備好了」。休息中的人不進任何新產生的場次（四種自動排程方式皆然），等待場數凍結；名單上所有人即時看到「☕ 休息中」。狀態存在後端，重新整理、換輪都不會變。 |
| US2 已排好的場次 | 按下休息的當下**不改任何場次**。叫場時先叫沒有休息者的場次；只剩有休息者的場次時，公平輪替雙打、個人全混搭在叫場那一刻找一位**現在就能上場**的替補，單打循環、固定搭檔保留那一場等他回來。回來時補上這一輪漏掉的場次，有空場就立刻叫場。這一輪被休息卡住、而下一輪排得出來時，自動進入下一輪會直接換輪。 |
| US3 不能插隊 | 休息期間打的比賽不算「坐著等」（保存休息區間），回來時打過的場數補到其他人的下中位數（`played_credit`，只用於排程優先順序）。 |
| US4 管理員代為切換 | 管理頁名單每一列一顆精簡按鈕（含團長）。手動安排、互換、替換選單裡休息中的人加上「（休息中）」但仍可選。 |

另加使用者要求的**提醒**：按休息若會讓人失去場次，後端先拒絕並回 409 `REST_ENDS_ROUND`（含場次數與 `immediate`），畫面跳出確認框，確認後才生效。兩種情況：

- **立刻**：這一輪會立刻結束（沒有比賽在打、剩下的場次全都在等他、開著自動換輪、下一輪排得出來）——「本輪還沒打的 N 場比賽會被取消，並直接進入下一輪」。判斷與真正換輪用同一個函式。
- **之後**：開著自動換輪、單打循環或固定搭檔、他有保留中的場次、下一輪排得出來——「這一輪結束前你沒回來的話，你還沒打的 N 場比賽會被取消」。雙打公平輪替、個人全混搭輪到時由替補上場，不會被取消，所以不提醒。

## 授權邊界（憲章「技術治理」要求）

- **伺服器是唯一可信來源**：`roster.restChanged` 只由後端在 commit 之後發布；前端不自行廣播、不樂觀更新他人畫面，收到事件一律重抓。「這場算保留還是替補」「這一輪是否被卡住」「替補是誰」「要不要提醒」全部由後端判斷並放進回應。
- **本人端點** `PUT /groups/{id}/roster/{entry}/rest-state` 的擁有權檢查與離團**共用同一個函式**（`_require_owned_active_entry()`，由 `leave_group()` 抽出）；他人、錯誤的訪客 token、未帶身分、已離開、別團、不存在——六種拒絕回應逐位相同，不洩漏該列是否存在。授權檢查先於提醒判斷，無權者不會從 409 得知這一輪的狀況。
- **管理員端點** `PUT /groups/{id}/members/{entry}/rest-state` 為 `require_admin`，只出現在管理頁。計分板、單一場地控制面板、全部場地控制面板的連結 token 無法呼叫任一支（契約測試涵蓋）。

## 讀程式才發現、規格沒寫到的事（設計已涵蓋）

1. `wait_count` 以外還有兩個會讓休息者插隊的來源：「坐著等了幾場」是從比賽時間推導的（休息一小時＝等了十幾場），以及挑人的第二順位「打得少的人優先」（回來後一路優先到追平）。前者以休息區間扣除，後者以 `played_credit` 處理。模擬測試在**關閉這兩個修正**時，回來的人比一直在場邊的人多打 5～7 個百分點；開啟時為 0 或負。
2. `_get_active_roster_ordered()` 的 7 個呼叫端中有 2 個是在建立**正式搭檔**；休息不應影響搭檔關係（FR-034），因此拆成 ready／active 兩個版本。
3. 固定搭檔（手動）若只把休息者排除，他的搭檔會被 017 的自動補位臨時配給別人，休息者一回來就落單——整隊暫停，搭檔不進自動補位。

## 實作中發現並修正的問題

- **沒開始過的團會自己開局**：開著自動換輪時，在還沒有任何一輪的團裡按休息／準備好了，由休息觸發的換輪會把第一輪排出來。改為只有產生過至少一輪才會由休息觸發換輪。（整合測試寫到這裡時發現。）
- 成員頁的 `load()` 在 effect 內同步執行，新讀的 signal 讓 effect 多跑一次、多載入一次；改為 `untracked`。
- 場地等待原因原本在五個畫面各自寫死兩種；抽成 `waitingReasonKey()`，不認得的值退回「等待下一輪」。

## 提醒規則的一次修訂（2026-09-20）

最初依規格只在「按下去這一輪就**立刻**結束」時提醒。實作後確認這個狀態在正常流程中幾乎只出現在「管理員規劃好一輪、還沒按開始」時；最常見的「別人還在打時按休息，等那場打完這一輪才因他而結束」反而不會提醒。使用者決定改成**一按休息就提醒**——加入上面「之後」那一種。休息後畫面上的「你還有 N 場保留中」說明文字保留，作為持續提醒。
