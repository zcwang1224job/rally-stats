# Feature Specification: 會員個人設定（四大分區）

**Feature Branch**: `022-member-personal-settings`

**Created**: 2026-09-13

**Status**: Draft

**Input**: User description: "會員專區 -> 個人設定中，設計四個主要設定功能，包含 1. 基本設定（暱稱、語言偏好（目前只有繁體中文，未來會擴充多種語言）） 2. 帳號詳細資訊（登入紀錄） 3. 安全性（變更密碼（需輸入當前密碼、新密碼、再次輸入新密碼）） 4. 隱私設定 （能否可以被搜尋到、好友能否可以查看到我的戰績）"

## Clarifications

### Session 2026-09-13

- Q: 隱私設定（允許被搜尋 / 好友可查看戰績）的預設值，應該是「開啟（維持現況）」還是「關閉（預設保護隱私）」？ → A: 兩項皆預設開啟（沿用現況，不造成既有會員行為被動改變）
- Q: 「好友可查看我的戰績」這項設定，應涵蓋逐場對戰紀錄明細、彙總統計（勝率等），還是兩者皆是？ → A: 涵蓋全部：逐場對戰紀錄明細＋彙總統計（勝率等）皆一併受此開關管控
- Q: 登入紀錄應顯示到什麼細節（僅時間戳記／時間＋IP-地理位置／時間＋裝置類別）？ → A: 時間戳記＋裝置類別（例如桌面／行動裝置、瀏覽器名稱），不蒐集 IP／地理位置——避免 GeoIP 精確度低、公用網路誤判、以及提前將 IP 保留/刪除政策（憲章已記錄為延後項目）拉入本次範圍
- Q: 什麼樣的行為算作「一次登入事件」（僅主動登入／主動登入＋每次 token refresh 皆算）？ → A: 僅「主動登入」（Email＋密碼提交）算一次事件，token refresh（背景延續既有 session）不記錄

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 基本設定：暱稱與語言偏好 (Priority: P1)

已驗證的會員進入「會員專區 -> 個人設定」，在「基本設定」分區中查看並修改自己的暱稱，以及查看/選擇語言偏好（目前僅提供繁體中文一個選項，但介面需以「可選擇清單」的形式呈現，而非寫死單一語言，讓未來新增語言時使用者能直接切換而不需重新設計此分區）。

**Why this priority**：暱稱是會員在整個系統中（賽程、對戰紀錄、好友列表）被辨識的主要身分呈現方式，也是「個人設定」頁面既有、使用頻率最高的既有功能；將其納入新分區結構是此功能上線後使用者最先接觸、最頻繁互動的部分。

**Independent Test**：可獨立測試——登入已驗證會員帳號，進入個人設定的「基本設定」分區，修改暱稱並儲存，重新整理頁面後確認新暱稱已生效；並確認語言偏好選單存在且目前僅可選「繁體中文」。

**Acceptance Scenarios**:

1. **Given** 已驗證會員開啟「個人設定」頁面，**When** 該會員進入「基本設定」分區，**Then** 系統顯示該會員目前的暱稱與目前的語言偏好（預設繁體中文）。
2. **Given** 會員在「基本設定」分區輸入一個合法的新暱稱，**When** 會員儲存變更，**Then** 系統成功儲存新暱稱、顯示明確的成功提示，且此後系統各處顯示該會員身分之處皆反映新暱稱。
3. **Given** 會員在「基本設定」分區查看語言偏好選單，**When** 選單開啟，**Then** 選單以「可選擇清單」形式呈現且目前僅有「繁體中文」一個選項並為預設選取狀態，UI 元件本身不因僅有單一語言而被省略或以純文字取代。
4. **Given** 會員將暱稱欄位留空或輸入超過長度上限的內容，**When** 會員嘗試儲存，**Then** 系統拒絕此次變更、以明確理由提示錯誤，且不影響原本已儲存的暱稱。

### User Story 2 - 帳號詳細資訊：登入紀錄 (Priority: P2)

已驗證的會員進入「帳號詳細資訊」分區，查看自己帳號近期的登入紀錄，藉此確認是否有非本人的登入行為。

**Why this priority**：登入紀錄屬於唯讀的資訊呈現功能，不涉及資料寫入或其他會員的權限判斷，風險最低、實作範圍最單純，但對會員的帳號安全感知有直接價值，故排序其次。

**Independent Test**：可獨立測試——以同一帳號登入兩次（不同時間/裝置），進入「帳號詳細資訊」分區，確認畫面列出至少兩筆登入紀錄且依時間新到舊排序。

**Acceptance Scenarios**:

1. **Given** 會員帳號過去有多筆登入紀錄，**When** 會員開啟「帳號詳細資訊」分區，**Then** 系統以時間由新到舊列出登入紀錄，每筆紀錄至少包含登入時間與裝置類別，不含 IP 位址或地理位置。
2. **Given** 會員是剛完成註冊與驗證、僅登入過一次（即目前這次）的帳號，**When** 會員開啟「帳號詳細資訊」分區，**Then** 畫面至少顯示這一筆登入紀錄，不會呈現空白或令人困惑的空狀態。
3. **Given** 登入紀錄筆數超過單頁可顯示的數量，**When** 會員瀏覽該分區，**Then** 系統提供讓會員能查看更早紀錄的方式（例如分頁或載入更多），不會單純截斷或遺漏資料而不告知。

### User Story 3 - 安全性：變更密碼 (Priority: P3)

已驗證的會員進入「安全性」分區，透過輸入「目前密碼、新密碼、再次輸入新密碼」三個欄位來變更自己的登入密碼。

**Why this priority**：變更密碼的核心邏輯在系統中已存在（既有的當前密碼驗證、新密碼確認、其他裝置登入狀態失效等行為），此項工作主要是將既有能力整併進新的「個人設定」四分區結構中並確保呈現一致，故排序在全新能力（登入紀錄、隱私設定）之後、但仍先於隱私設定，因其屬於帳號安全本質的核心保護機制。

**Independent Test**：可獨立測試——在「安全性」分區輸入正確的目前密碼與相符的兩次新密碼並送出，確認密碼變更成功；以舊密碼重新登入應失敗、以新密碼登入應成功。

**Acceptance Scenarios**:

1. **Given** 會員在「安全性」分區輸入正確的目前密碼、且新密碼與再次輸入的新密碼一致並符合密碼強度規則，**When** 會員送出變更，**Then** 系統成功更新密碼並顯示明確的成功提示。
2. **Given** 會員輸入的「目前密碼」有誤，**When** 會員送出變更，**Then** 系統拒絕此次變更、明確提示目前密碼錯誤，且不影響原密碼。
3. **Given** 會員輸入的「新密碼」與「再次輸入新密碼」兩者不一致，**When** 會員送出變更，**Then** 系統在送出前或送出時明確提示兩者不相符，不呼叫後端變更密碼。
4. **Given** 會員成功變更密碼，**When** 變更完成，**Then** 該會員在其他裝置上原有的登入狀態 MUST 失效（需重新登入），但發起此次變更的當前裝置 MUST 維持登入狀態不中斷。

---

### User Story 4 - 隱私設定：可搜尋性與好友戰績可視性 (Priority: P4)

已驗證的會員進入「隱私設定」分區，控制兩件事：（a）自己是否能被其他會員透過搜尋找到；（b）已加為好友的會員是否能查看自己的對戰紀錄／戰績。

**Why this priority**：此為全新能力中涉及「影響其他使用者可以看到什麼」的功能，牽涉範圍最廣（需同時影響搜尋功能與好友戰績檢視功能兩個既有/相關入口），且屬於隱私類判斷，需最謹慎設計與測試，故排在四者之末，待前三者的結構與資料模型底定後再整合。

**Independent Test**：可獨立測試——關閉「允許被搜尋」後，以另一會員帳號嘗試搜尋該會員應找不到；關閉「好友可查看戰績」後，以已是好友關係的另一會員帳號查看該會員戰績應被拒絕查看。

**Acceptance Scenarios**:

1. **Given** 會員在「隱私設定」分區將「允許被搜尋」設為關閉，**When** 另一位會員嘗試以此會員的可搜尋識別資訊進行搜尋，**Then** 系統回應「找不到此會員」，不揭露此帳號存在。
2. **Given** 會員在「隱私設定」分區將「允許被搜尋」設為開啟，**When** 另一位會員以正確的可搜尋識別資訊進行搜尋，**Then** 系統正常回傳此會員的公開資訊。
3. **Given** 會員在「隱私設定」分區將「好友可查看我的戰績」設為關閉，**When** 一位已通過好友邀請、彼此為好友關係的會員嘗試查看此會員的對戰紀錄／戰績，**Then** 系統拒絕顯示，並提示此會員已將戰績設為不公開。
4. **Given** 會員在「隱私設定」分區將「好友可查看我的戰績」設為開啟，**When** 一位已是好友關係的會員查看此會員的對戰紀錄／戰績，**Then** 系統正常顯示。
5. **Given** 兩位會員尚未成立好友關係，**When** 其中一方嘗試查看對方的對戰紀錄／戰績，**Then** 無論「好友可查看我的戰績」設定為何，系統皆 MUST 拒絕顯示（此設定僅開放給已成立的好友關係，非好友關係一律不可查看）。
6. **Given** 會員變更任一隱私設定，**When** 變更送出，**Then** 系統立即儲存並顯示明確的成功提示，且新設定立即對後續的搜尋／戰績查看請求生效，不需等待重新登入或快取過期。

---

### Edge Cases

- 會員在四個分區中的任一分區操作到一半（表單已填寫但尚未送出）時切換到其他分區或離開頁面：系統不需保留未送出的暫存內容（重新進入該分區時欄位回復為目前已儲存的值）。
- 會員將暱稱改成與另一位會員完全相同的暱稱：系統 MUST 允許（暱稱在系統中本非唯一識別欄位，既有行為維持不變）。
- 會員嘗試將新密碼設為與目前密碼相同：系統 MUST 視為合法的變更請求並允許送出（不強制新舊密碼必須不同）。
- 尚未完成 Email 驗證的會員（見既有的信箱驗證關卡）嘗試開啟「個人設定」任一分區：系統 MUST 沿用既有規則，導向驗證提示畫面，不開放任何分區內容。
- 會員帳號目前沒有「好友」關係（好友清單為空）：「好友可查看我的戰績」設定仍可正常開關與儲存，僅是暫時沒有任何人受此設定影響。
- 使用行動裝置小螢幕開啟「個人設定」頁面：四個分區 MUST 仍可正常切換與操作，不因螢幕寬度而遺漏任一分區的功能。
- 會員透過好友戰績端點查看的 `member_id` 恰好是自己：系統 MUST 拒絕，回應明確的「請改用自己的戰績頁面」錯誤，MUST NOT 落入好友關係檢查（避免誤判為「尚未成立好友關係」）。

## Requirements *(mandatory)*

### Functional Requirements

**基本設定**

- **FR-001**: 系統 MUST 在「個人設定」頁面提供「基本設定」分區，顯示會員目前的暱稱與目前的語言偏好。
- **FR-002**: 會員 MUST 能在「基本設定」分區修改暱稱並儲存，儲存成功後 MUST 顯示明確的成功提示。
- **FR-003**: 系統 MUST 對暱稱輸入套用既有的合法性檢查（必填、長度上限），不符合規則時 MUST 拒絕儲存並提示具體原因。
- **FR-004**: 系統 MUST 以可選擇清單（而非寫死的純文字）呈現語言偏好，即使目前僅有「繁體中文」一個選項；此清單結構 MUST 支援未來新增語言選項而不需重新設計此分區的呈現方式。
- **FR-005**: 會員選擇語言偏好後，系統 MUST 儲存此偏好於會員帳號資料中。

**帳號詳細資訊**

- **FR-006**: 系統 MUST 在「個人設定」頁面提供「帳號詳細資訊」分區，顯示該會員帳號的登入紀錄。
- **FR-007**: 系統 MUST 記錄會員每一次主動登入事件（即透過 Email＋密碼或未來其他登入方式主動提交的登入請求），至少包含登入發生的時間與裝置類別（例如桌面瀏覽器／行動裝置瀏覽器），MUST NOT 記錄或顯示 IP 位址或地理位置；已登入 session 期間的 token 自動換新（refresh）MUST NOT 被視為一次獨立登入事件、MUST NOT 產生新的登入紀錄。
- **FR-008**: 登入紀錄 MUST 依時間由新到舊排序呈現給會員。
- **FR-009**: 當登入紀錄筆數超過單頁可顯示數量時，系統 MUST 提供讓會員查看更早紀錄的方式。
- **FR-010**: 登入紀錄 MUST 僅該會員本人可查看，MUST NOT 對其他會員（含好友）公開。

**安全性**

- **FR-011**: 系統 MUST 在「個人設定」頁面提供「安全性」分區，讓會員透過輸入「目前密碼、新密碼、再次輸入新密碼」三個欄位變更密碼。
- **FR-012**: 系統 MUST 在允許變更前驗證「目前密碼」是否正確；不正確時 MUST 拒絕變更並明確提示。
- **FR-013**: 系統 MUST 驗證「新密碼」與「再次輸入新密碼」兩欄位內容一致；不一致時 MUST 拒絕變更並明確提示，不得送出至後端處理。
- **FR-014**: 系統 MUST 對新密碼套用既有的密碼強度規則，不符合規則時 MUST 拒絕變更並提示具體原因。
- **FR-015**: 密碼成功變更後，系統 MUST 使該會員在其他裝置上既有的登入狀態全數失效（需重新登入），並 MUST 維持發起此次變更之當前裝置的登入狀態不中斷。

**隱私設定**

- **FR-016**: 系統 MUST 在「個人設定」頁面提供「隱私設定」分區，讓會員控制「是否允許被其他會員搜尋到」與「是否允許好友查看自己的對戰紀錄／戰績」兩項設定。
- **FR-017**: 當會員將「允許被搜尋」設為關閉時，其他會員透過搜尋 MUST 無法找到此會員（系統回應方式 MUST 與「查無此人」一致，不得洩露「此帳號存在但已隱藏」的資訊差異）。
- **FR-018**: 當會員將「好友可查看我的戰績」設為關閉時，即使是已成立好友關係的會員，也 MUST 無法查看此會員的對戰紀錄／戰績；此限制 MUST 同時涵蓋逐場對戰紀錄明細（誰對誰、比分、時間等）與彙總統計數據（例如勝率、勝負場數），MUST NOT 僅限縮其中一種而放行另一種。
- **FR-019**: 無論「好友可查看我的戰績」設定為何，尚未與此會員成立好友關係的其他會員 MUST 一律無法查看其對戰紀錄／戰績（此設定僅放寬「好友」範圍內的可視性，MUST NOT 影響非好友的既有限制範圍）。
- **FR-020**: 隱私設定的變更 MUST 立即生效於後續的搜尋與戰績查看請求，MUST NOT 需要重新登入或等待快取過期才生效。
- **FR-021**: 隱私設定變更儲存成功後，系統 MUST 顯示明確的成功提示，與其他三個分區的儲存回饋方式一致。
- **FR-022**: 「允許被搜尋」設定 MUST 預設為開啟，沿用既有搜尋功能對所有已驗證會員無差別開放的現況，避免既有會員因本功能上線而被動變成「找不到」。
- **FR-023**: 「好友可查看我的戰績」設定 MUST 預設為開啟。

**跨分區共通**

- **FR-024**: 「個人設定」頁面 MUST 以四個獨立分區（基本設定、帳號詳細資訊、安全性、隱私設定）呈現，會員 MUST 能在不離開頁面的情況下切換分區。
- **FR-025**: 未完成 Email 驗證的會員 MUST NOT 能開啟「個人設定」任一分區，MUST 沿用既有的驗證關卡導向規則。
- **FR-026**: 每個分區內的儲存操作 MUST 各自獨立（例如僅儲存「基本設定」不影響「安全性」分區尚未送出的內容），不得互相覆蓋彼此的暫存輸入。

### Key Entities

- **會員語言偏好（Language Preference）**：附屬於會員帳號的一個屬性，記錄該會員目前選擇的顯示語言；目前系統僅提供一個有效值（繁體中文），但此屬性的存在方式 MUST 支援未來擴充為多個有效值。
- **登入紀錄（Login Record）**：代表會員帳號一次「主動登入」事件（不含 token refresh），關聯至該會員，至少包含登入發生時間與裝置類別（例如桌面／行動裝置瀏覽器），MUST NOT 包含 IP 位址或地理位置，依會員讀取需求由新到舊呈現；僅供該會員本人查閱。
- **隱私設定（Privacy Setting）**：附屬於會員帳號的一組屬性，包含「是否允許被搜尋」與「是否允許好友查看戰績」兩個獨立的可切換狀態，兩者預設值皆為開啟（見 FR-022、FR-023）。
- **好友關係（Friend Relationship）**：既有實體（沿用既有好友系統中「已成立的好友關係」判斷），本功能僅新增以此關係為前提的戰績可視性判斷，不改變好友關係本身的建立/解除邏輯。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 已驗證會員能在 30 秒內（從進入「個人設定」頁面起算）找到並開啟四個分區中的任一個，無需額外說明或教學。
- **SC-002**: 會員在「基本設定」分區修改暱稱或語言偏好後，變更在 2 秒內獲得明確的成功或失敗回饋。
- **SC-003**: 100% 的成功登入事件皆能在會員下次查看「帳號詳細資訊」分區時被看到（不遺漏、不延遲超過一次頁面重新整理）。
- **SC-004**: 密碼變更流程中，輸入錯誤的目前密碼或不一致的新密碼兩次輸入時，100% 的情況下系統會在會員送出前後明確指出具體錯誤原因，而非泛用錯誤訊息。
- **SC-005**: 關閉「允許被搜尋」後，100% 的其他會員搜尋嘗試皆無法找到此帳號；重新開啟後，100% 的正確搜尋皆能立即（不超過一次操作的等待時間）找到此帳號。
- **SC-006**: 關閉「好友可查看我的戰績」後，100% 的好友查看嘗試皆被拒絕；此限制對非好友的查看嘗試 100% 維持既有的拒絕行為不變。
- **SC-007**: 四個分區的儲存成功提示呈現方式一致，使用者無需针對不同分區學習不同的「儲存是否成功」判讀方式。

## Assumptions

- **登入紀錄的保留範圍**：未特別要求登入紀錄需永久保留或指定確切保留筆數/期間，假設系統僅需保留「近期」登入紀錄（例如最近數十筆或數個月內，實作規劃階段再決定精確數字），超出範圍的舊紀錄可被系統自然淘汰，不影響本功能的核心價值（協助會員察覺近期異常登入）。
- **登入紀錄呈現的裝置/來源細節**：已於 Clarifications 段落確認為「時間戳記＋裝置類別」（見 FR-007），MUST NOT 蒐集或顯示 IP 位址／地理位置。
- **隱私設定的預設值**：已於 Clarifications 段落確認為「兩項皆預設開啟」（見 FR-022、FR-023），會員可依個人需求主動關閉。
- **語言偏好對其他既有畫面文字的實際影響範圍**：由於系統目前僅上線繁體中文，本功能範圍僅涵蓋「讓會員可以查看與選擇語言偏好、且此選擇被儲存」，不涵蓋「新增第二種語言的實際翻譯內容」——後者屬於未來語言擴充時的獨立工作範圍。
- **暱稱與語言偏好變更不會回溯影響會員過去已產生的歷史紀錄**（例如過去對戰紀錄中顯示的當下暱稱快照），沿用既有系統對「設定變更僅影響未來」的一貫原則。
- **本功能不涉及會員的 Email 或帳號刪除等資料保留/刪除政策**，此類事項已於專案層級記錄為刻意延後的未來規劃事項，不在本次規格範圍內。
