# Feature Specification: 決勝分二次確認

**Feature Branch**: `feature/match-point-confirm`

**Created**: 2026-09-20

**Status**: Draft

**Input**: User description: "比賽決勝點時，如果沒有開啟比賽詳細設定，按下決勝分的「+」按鈕要先跳出二次確認，說明確定之後比賽即結束、計入戰績且無法復原。四個計分畫面（單一場地控制頁面、全場地控制板、記分板、開團管理頁場地控制）都要加。詳細設定開啟時維持現狀，因為詳細記錄視窗本來就有「取消這一分」可以退。"

## 背景

計分時最不可逆的一按，是讓比賽結束的那一分。

**開啟「比賽詳細設定」的團已經有退路**：按下「+」之後會跳出詳細記錄視窗，視窗裡的「取消這一分」可以把剛加上的分收回——即使那一分已經讓比賽結束，系統也會一併撤銷比賽的結束判定，讓比賽回到進行中。

**沒有開啟詳細設定的團什麼退路都沒有**，而且情況比「沒有復原鍵」更糟：

1. **「-1」會靜默失效。** 比賽一旦結束，任何加減分都不會生效，畫面上的比分紋風不動。計分者按了「-1」卻什麼都沒發生，第一反應通常是「我是不是沒按到」而再按幾次，完全不知道真正的原因是比賽已經結束了。
2. **那一分寫下的是永久紀錄。** 自然達標結束的比賽會產生比賽結果、計入雙方戰績、對戰紀錄與排名。這和「提前結束」不同——提前結束的比賽視為已捨棄、不計入任何統計；但決勝分結束的比賽是真的算數的。
3. **現場最容易按錯的就是這一按。** 場邊計分靠手指在小螢幕上快點，按錯邊、幫對手多按一下都很常見。平常按錯還能用「-1」修正，唯獨決勝分按錯之後沒有任何辦法。

也就是說，在整個計分流程裡，唯一「一按定生死、而且完全沒有提示」的操作，就是簡易模式的決勝分。本功能替它補上二次確認，把後果講清楚再送出。

## Clarifications

### Session 2026-09-20

- Q: 哪些計分畫面要加？ → A: **四個都加**——單一場地控制頁面、全場地控制板、記分板、開團管理頁場地控制。憲章原則 V 把「不可逆操作必須二次確認」訂為通用原則，而且誤按風險在公開連結畫面其實更高（隨手在場邊計分的人不一定是管理員）。四個畫面行為不一致反而會讓人困惑。
- Q: 詳細設定開啟時要不要也跳？ → A: **不要**。詳細記錄視窗本來就有「取消這一分」，再加一層確認等於同一件事問兩次，反而拖慢比賽節奏。
- Q: 「-1」要不要跳？ → A: 不要。減分是修正手段，不會結束比賽。
- Q: 確認框要說什麼？ → A: 要講清楚三件事——**這一分會讓比賽結束**、**結果會計入戰績**、**之後無法復原**。只說「確定嗎？」沒有資訊量；而「不能改分數」也不夠準確，真正的後果是寫下一筆算數的比賽紀錄。
- Q: 決勝與否依團的當下設定還是比賽的設定？ → A: 依**這場比賽**建立當下的目標分／上限分快照，與既有的「設定不回溯影響進行中比賽」規則一致。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 簡易模式按下決勝分時先確認 (Priority: P1)

我在場邊用控制頁面計分，這個團沒有開啟比賽詳細設定。比數來到 20:15，我方再得一分就贏了。我按下「+」——這次畫面沒有直接加分，而是先跳出一個確認框，告訴我這一分會結束比賽、結果會計入戰績、而且之後無法復原。我確認後分數才加上去，比賽結束。

**Why this priority**：這是整個功能的核心價值，也是使用者描述裡唯一明講的需求。只做這一則，就已經把「一按定生死且毫無提示」的缺口補起來了。

**Independent Test**：開一個未啟用詳細設定的團，把一場比賽打到差一分結束，按下決勝分的「+」，驗證確認框會出現、內容說明了後果、確認後比賽才結束。

**Acceptance Scenarios**:

1. **Given** 一場未啟用詳細設定、且某隊再得一分即可獲勝的進行中比賽, **When** 計分者按下該隊的「+」, **Then** 系統 MUST 先顯示確認框，且 MUST NOT 在確認前改變任何比分。
2. **Given** 決勝分的確認框已顯示, **When** 計分者確認, **Then** 該分 MUST 被計入、比賽 MUST 依既有規則結束並產生比賽結果。
3. **Given** 決勝分的確認框已顯示, **When** 計分者取消, **Then** 比分 MUST 維持不變、比賽 MUST 仍在進行中，且計分者 MUST 能立即繼續計分（包含再次按下同一顆「+」）。
4. **Given** 確認框顯示中, **When** 計分者閱讀其內容, **Then** 內容 MUST 說明這一分會結束比賽、比賽結果會計入戰績、以及確認後無法復原。

---

### User Story 2 - 只在真正該出現的時候出現 (Priority: P2)

我在同一場比賽裡一路計分。從 0:0 打到 19:15，每一下「+」都是直接加分，沒有任何多餘的視窗擋路。打到平手加賽時也一樣——20:20 再得一分只是 21:20，還沒贏，所以不會跳確認。只有真正會結束比賽的那一分才會問我。

**Why this priority**：確認框如果出現得太浮濫，計分者會養成不看內容直接點確認的習慣，這個功能就等於白做，還拖慢了比賽節奏。與 US1 分開是因為 US1 交付後功能已可用，這一則保護的是它的長期有效性。

**Independent Test**：在一場未啟用詳細設定的比賽中，從 0:0 連續計分到比賽結束，記錄每一次「+」是否跳出確認框，驗證只有最後那一分跳。

**Acceptance Scenarios**:

1. **Given** 一場比分距離結束還差兩分以上的比賽, **When** 計分者按下「+」, **Then** 系統 MUST 直接加分，MUST NOT 顯示任何確認框。
2. **Given** 一場採平手加賽規則、雙方同分且尚未達上限分的比賽（例如目標 21 分、現為 20:20）, **When** 計分者按下「+」, **Then** 系統 MUST 直接加分——因為 21:20 只領先一分，尚未獲勝。
3. **Given** 一場比分已達上限分前一分的比賽（例如上限 30 分、現為 29:29）, **When** 計分者按下「+」, **Then** 系統 MUST 顯示確認框——達到上限分即獲勝，不受領先分數限制。
4. **Given** 任何比賽狀態, **When** 計分者按下「-1」, **Then** 系統 MUST 直接減分，MUST NOT 顯示確認框。
5. **Given** 一場**已啟用**詳細設定的比賽來到決勝分, **When** 計分者按下「+」, **Then** 系統 MUST 維持現行行為（直接加分並開啟詳細記錄視窗），MUST NOT 額外顯示本功能的確認框。

---

### User Story 3 - 四個計分畫面行為一致 (Priority: P3)

不管我是用管理頁的場地控制、公開的單一場地控制連結、全場地控制板，還是有開放計分的記分板，決勝分的行為都一樣。我不需要記得「在哪個畫面要小心一點」。

**Why this priority**：US1 在任何單一畫面上交付後就已有價值，但只做一個畫面會留下不一致——同一顆決勝分在 A 畫面會問、在 B 畫面不會問，反而製造新的困惑。

**Independent Test**：以同一場未啟用詳細設定的比賽，分別從四個畫面按下決勝分的「+」，驗證四者都跳出確認框，且文案與行為相同。

**Acceptance Scenarios**:

1. **Given** 同一場未啟用詳細設定、來到決勝分的比賽, **When** 計分者分別從四個計分畫面按下「+」, **Then** 四個畫面 MUST 都顯示確認框，且說明內容與確認／取消的行為 MUST 一致。
2. **Given** 任一畫面顯示確認框期間, **When** 另一個畫面的計分者讓同一場比賽的比分改變, **Then** 系統 MUST NOT 因此產生錯誤或不一致的比分（確認的結果仍以伺服器的判定為準）。

---

### Edge Cases

- **雙方同時都在決勝分**（例如 20:20 之後一路到 29:29，或目標分 21 時的 20:19 對 20:20 情境）：任一隊的「+」只要會結束比賽就 MUST 各自跳出確認框。
- **確認框開啟期間比賽狀態改變**（另一位計分者先得分、比賽被提前結束、或換輪）：確認後若該分已不再適用，系統 MUST 以伺服器的判定為準，MUST NOT 讓畫面停在錯誤或不一致的狀態。
- **確認後那一分結果上沒有結束比賽**（例如期間對手已先得分，使這一分不再是決勝分）：該分 MUST 正常計入，比賽 MUST 繼續，MUST NOT 因為曾經顯示過確認框就強制結束比賽。
- **離線／連線中斷**：確認框與其確認動作 MUST 依既有的離線規則停用，與其他計分操作一致。
- **比賽建立後才改團設定**：決勝與否 MUST 依該場比賽建立當下的目標分／上限分，MUST NOT 因為管理員中途調整團設定而改變進行中比賽的確認時機。
- **同一顆「+」被連續快速點擊**：系統 MUST NOT 因此送出兩分，也 MUST NOT 疊出兩個確認框。
- **沒有計分權限的畫面**（未開放計分的記分板）：本功能不改變其是否能計分，僅在能計分時套用相同規則。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 當比賽**未啟用**詳細設定，且按下的「+」會使該隊獲勝並結束比賽時，系統 MUST 先顯示二次確認，MUST NOT 在確認前送出該分。
- **FR-002**: 確認內容 MUST 明確說明三件事：這一分會讓比賽結束、比賽結果會計入戰績、確認後無法復原。
- **FR-003**: 計分者確認後，系統 MUST 送出該分，後續結束判定與比賽結果的產生一律沿用既有規則。
- **FR-004**: 計分者取消後，系統 MUST NOT 送出任何分數，比分與比賽狀態 MUST 完全不變，且 MUST 能立即繼續計分。
- **FR-005**: 當比賽**已啟用**詳細設定時，系統 MUST 維持現行行為，MUST NOT 顯示本功能的確認框。
- **FR-006**: 「-1」按鈕 MUST NOT 顯示本功能的確認框。
- **FR-007**: 當按下的「+」不會結束比賽時，系統 MUST 直接送出該分，MUST NOT 顯示確認框。
- **FR-008**: 是否為決勝分 MUST 依據該場比賽建立當下的目標分與上限分快照，MUST NOT 依據團當下的設定值。
- **FR-009**: 決勝判定 MUST 與系統實際的獲勝規則一致——達到上限分即獲勝，或達到目標分且領先對手 2 分以上；平手加賽門檻不參與此判定。
- **FR-010**: 當雙方都處於「再得一分即獲勝」時，兩隊的「+」MUST 各自顯示確認框。
- **FR-011**: 單一場地控制頁面、全場地控制板、記分板、開團管理頁場地控制四個畫面 MUST 有相同的判定條件、說明文字與確認／取消行為。
- **FR-012**: 確認框與其確認動作 MUST 依既有的離線規則停用，規則與其他計分操作一致。
- **FR-013**: 確認後若伺服器判定該分並未結束比賽，系統 MUST 接受伺服器的判定，MUST NOT 依前端的預測強制結束比賽。
- **FR-014**: 系統 MUST 防止重複送分：連續快速點擊同一顆「+」MUST NOT 產生兩分，也 MUST NOT 疊出兩個確認框。
- **FR-015**: 所有新增的畫面文字 MUST 透過多語系機制提供（繁體中文與英文），MUST NOT 硬寫於程式中。

### Key Entities

- **比賽的計分規則快照**：每場比賽在建立時保存的目標分、上限分（與平手加賽門檻），決定這場比賽如何算贏；該場比賽之後一律依此快照判定，不受團設定後續變更影響。
- **決勝分**：在當前比分下，某一隊再得一分就會依上述規則獲勝的狀態。雙方可能同時處於此狀態。
- **比賽結果**：比賽自然達標結束時產生的永久紀錄，計入雙方戰績、對戰紀錄與排名；提前結束或被捨棄的比賽不產生此紀錄。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在未啟用詳細設定的比賽中，100% 會結束比賽的「+」都會先出現確認，沒有任何一次直接結束比賽。
- **SC-002**: 在同一場比賽中，不會結束比賽的每一次「+」都維持 0 個額外點擊與 0 個額外視窗——計分節奏與本功能實作前相同。
- **SC-003**: 計分者在確認框上取消後，比分與比賽狀態 100% 與按下前相同，且能立即繼續計分。
- **SC-004**: 四個計分畫面對同一場比賽的同一顆決勝分，判定結果與顯示文字 100% 一致。
- **SC-005**: 確認框的文字能讓計分者在不詢問他人的情況下說出「確認後比賽會結束並計入戰績」——以現場或使用者測試方式驗證。
- **SC-006**: 已啟用詳細設定的比賽，其計分流程的點擊次數與視窗數量與本功能實作前完全相同（0 個新增）。

## Assumptions

- **獲勝規則本身不變。** 本功能只在前端判斷「下一分會不會贏」，不重新定義、不放寬任何獲勝或結束條件；真正的判定仍由伺服器在收到該分後執行，前端的預測只用來決定要不要先問一句。
- **詳細模式已有足夠退路，不重複保護。** 詳細記錄視窗的「取消這一分」已涵蓋賽末點（會一併撤銷比賽的結束判定），因此詳細模式維持現狀。
- **沿用既有的二次確認介面樣式。** 系統既有的確認框（例如「提前結束」）已建立樣式與無障礙處理，本功能沿用同一套呈現方式，只是內容不同。
- **本功能不提供事後復原。** 使用者要的是事前確認。系統內部雖有撤銷比賽結束的能力（目前僅供詳細模式的「取消這一分」使用），但把它開放成簡易模式的事後復原鍵是另一個獨立的題目，不在本次範圍。
- **範圍限於四個計分畫面的「+」按鈕。** 不改變成員檢視頁、比賽紀錄頁或任何統計畫面。
- **新增文案會是本功能唯一的語系檔改動。** 確認框的標題與內文需要新的多語系字串（繁中與英文），其餘沿用既有文案。
